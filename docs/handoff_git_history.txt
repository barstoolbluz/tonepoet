+# Design Brief: DSD→PCM Reference Pathway and Manual/Expert Workflows
+
+**Status:** implementation-authoritative design commission deliverable  
+**Date:** 2026-07-18  
+**Evidence baseline:** SoX-ng 14.8.0.1 (`sox_ng-14.8.0.1`, commit `266aa9e777829a1b60959a1250b4c42597558639`)  
+**Implementation target:** the next tonepoet work round
+
+## Executive decision
+
+Tonepoet will replace its current single-command DSD→PCM path (`tonepoet-pipeline/src/plan.rs:1161-1243`, `tonepoet-pipeline/src/plugins.rs:1147-1175`) with two explicit pathways:
+
+1. **Reference** — a versioned, fail-closed, evidence-qualified native SoX-ng pathway for uncompressed DSD64, DSD128, and DSD256 DSF/DSDIFF sources. Its order is fixed:
+
+   ```text
+   explicit −12 dB headroom
+     → rate -u directly to target PCM rate
+     → target-rate profile sinc when defined
+     → PCM effects
+     → programme-wide true-peak measurement
+     → one constant restoration/compensation gain capped at −1 dBTP
+     → one terminal sample-format realization
+     → lossless encoding or containerization
+   ```
+
+2. **Manual** — a persisted, linear, structured workflow of SoX-ng, FFmpeg, and SSRC stages. Tonepoet owns executable selection, stage paths, cancellation, transcripts, verification, cleanup, and atomic publication. It does **not** insert or rewrite DSP policy.
+
+The Reference implementation is deliberately narrower than tonepoet's theoretical format matrix. It will not invent behavior where the evidence does not define or qualify it:
+
+- DSD128/DSD256 → 88.2 kHz is rejected until a target-limited profile is specified and qualified.
+- DSD128/DSD256 → 96 kHz is rejected until the intended B4-at-96 path is directly qualified.
+- DSD512/DSD1024 and standalone DSDIFF/DST are rejected by Reference v1.
+- Reference v1 is designed for policy-qualified mono/stereo sources, lossless PCM destinations, and the evidence-defined terminal-depth candidates: 16-bit integer, 24-bit integer, Float32, and Float64. A source/rate/depth/format cell is exposed only if it is frozen as supported when the immutable v1 policy is minted; native multichannel mapping remains unavailable.
+- Continuous CUE/SACD programme processing is a second implementation phase. Phase 1 rejects Reference conversions that would split a continuous DSD programme before processing.
+- B6 remains an explicit provisional profile and is unavailable in policy `sox_ng_14_8_0_1_v1`. Enabling it requires a new append-only policy ID after qualification; no build flag or mutable data gate may change the meaning of a persisted policy ID.
+
+These are product-visible planner errors, not runtime tool failures or silent fallback.
+

+## 0. Design basis and current-state constraints
+
+### 0.1 Evidence authority
+
+This design adopts the two supplied evidence documents without extending their empirical claims:
+
+- `docs/tonepoet_dsd_to_pcm_guidance_evidence_based_v9.md`
+- `docs/sox_ng_dsd_decimation_test_report_v5.md`
+
+The evidence establishes `rate -u → sinc`, explicit fixed headroom rather than `-G`, requested `sinc -a 180`, Reference profiles B1–B6, fixed DSD level compensation capped by true peak, final-only dither, process-before-split for continuous programmes, and a strict distinction between coherent stopband rejection, order nulls, and output noise. No direct commission/evidence conflict was found. The commission's compact B3/B4/B5 table is read together with v9's target-ceiling examples: the undefined DSD128/DSD256→88.2 kHz target-limited cells and conditionally qualified 96 kHz cells are not silently inferred.
+
+### 0.2 Current code facts that constrain the design
+
+The bundle still pins the `sox_ng` input at revision `482801f768d5075fcef1ec81968fd57a85433627`, not the evidence-qualified 14.8.0.1 commit (`flake.lock:142-160`). The implementation round must advance and lock that input before enabling any Reference cell; this design targets the evidence baseline, not the currently pinned binary.
+
+The pure planner carries source facts and complete `PipelineSettings` in `PlanRequest`, allocates deterministic intermediate and final work paths, and models finalization as `Finalization::AtomicRename` (`tonepoet-pipeline/src/plan.rs:18-36`, `tonepoet-pipeline/src/plan.rs:70-117`, `tonepoet-pipeline/src/plan.rs:633-644`). The low-level track executor currently removes a stale destination and then renames the planner-declared staged path (`src/convert/pipeline/track_executor.rs:701-714`), but the orchestration layer already has a stronger album publisher: it binds publication to retained authority, repairs interrupted publishes, assembles all album entries in a sibling temporary directory, writes the manifest into that directory, and publishes the directory by rename with backup/rollback handling (`src/convert/pipeline/stages.rs:18776-18938`, `src/convert/pipeline/stages.rs:18974-19077`, `src/convert/pipeline/stages.rs:19085-19276`). It also has a separate incremental existing-directory path (`src/convert/pipeline/stages.rs:19159-19182`, `src/convert/pipeline/stages.rs:19347-20079`). The new design must extend those authority domains rather than infer durability from the planner enum or create an unrelated publisher. In particular, the current whole-album manifest write is nonfatal (`src/convert/pipeline/stages.rs:19239-19253`) and the incremental manifest write is also nonfatal (`src/convert/pipeline/stages.rs:20068-20079`); neither is sufficient for native-v2 rerun authority.
+
+All DSD-to-PCM requests currently route through `plan_from_dsd`, which emits one `PlanOperation::DsdToPcm` either directly to a SoX-capable final format or to a WAV intermediate followed by final encoding (`tonepoet-pipeline/src/plan.rs:613-621`, `tonepoet-pipeline/src/plan.rs:1161-1243`). The SoX plugin is the only builder for that operation (`tonepoet-pipeline/src/plugins.rs:296-308`, `tonepoet-pipeline/src/plugins.rs:1147-1175`).
+
+The current effect builder performs `rate`, an optional single-cutoff `sinc`, gain/normalization, and optional dither in one static argv (`tonepoet-pipeline/src/plugins.rs:1614-1688`). Its current Auto gain is SoX `norm`, while Manual is a fixed `gain` and Disabled has a compatibility fixed-gain path (`tonepoet-pipeline/src/plugins.rs:1712-1738`).
+
+`ConversionPlan` execution currently receives a static `Vec<PlannedCommand>`. The executor converts and runs each command in sequence; no command result can bind an argument in a later command (`src/convert/pipeline/track_executor.rs:256-292`, `src/convert/pipeline/track_executor.rs:342-424`). Command records already preserve resolved argv, environment keys, output tails, exit state, and elapsed time (`src/convert/pipeline/track_executor.rs:491-569`).
+
+The orchestrator rejects arbitrary planner `ToolIdentifier::Custom` values; only registered built-ins map to runtime `ToolBinary` values (`src/convert/pipeline/planned_adapter.rs:35-46`). This is the correct trust boundary for Manual workflows and will be retained.
+
+`SourceInfo` currently carries the coarse DSF/DFF format, DSD representation, and rate, but a generic DFF fact cannot distinguish uncompressed DSDIFF/DSD from DSDIFF/DST, and it cannot preserve an original SACD area's encoding after realization (`tonepoet-pipeline/src/source.rs:8-64`, `tonepoet-pipeline/src/source.rs:129-178`). The conversion bridge already inspects DSDIFF `CMPR` and distinguishes DSF, DSDIFF/DSD, and DSDIFF/DST, but stores the result in a companion structure because `SourceInfo` cannot carry that encoding fact (`src/convert/pipeline/plan_bridge.rs:426-458`, `src/convert/pipeline/plan_bridge.rs:501-533`). Reference routing must move it into the planner input.
+
+The current DSD settings mix PCM→DSD and DSD→PCM concerns in one `DsdSettings`, including a dual-use `SincFilterSettings`; its defaults are explicitly sized for PCM→DSD upsampling (`tonepoet-pipeline/src/settings.rs:716-766`, `tonepoet-pipeline/src/settings.rs:781-812`). The DSD→PCM `Sinc` arm consumes those fields before `rate`, while the ordinary arm uses a single source-rate cutoff after `rate` (`tonepoet-pipeline/src/plugins.rs:1622-1677`). The redesign removes that dual use.
+
+The TUI currently exposes only DSD gain mode and fixed dB for DSD-source/PCM-target conversions (`src/tui/draw_output.rs:164-179`, `src/tui/app.rs:3538-3542`). It constructs default `DsdSettings` and overrides only the gain fields for that direction (`src/tui/convert_actions.rs:371-400`). TUI presets are version 3 and currently persist PCM→DSD filter choices but no DSD→PCM pathway, profile, gain policy, or workflow (`src/tui/presets.rs:29-75`, `src/tui/presets.rs:104-149`).
+
+The CLI currently constructs legacy `ConversionOptions`; full planner settings are optional queue fields, while the legacy bridge deliberately resets DSD settings to defaults and cannot represent the advanced resampler fields (`src/main.rs:967-1060`, `src/convert/formats.rs:605-612`, `src/convert/pipeline/unified_request.rs:499-540`, `src/convert/pipeline/unified_request.rs:544-580`). New DSD controls therefore use the full-settings path rather than expanding the lossy compatibility projection.
+
+The selected output container is also not wholly represented by `PipelineSettings`: `PipelineRequest` carries a separate `container_extension` plus raw `container_ffmpeg_flags` (`src/convert/pipeline/types.rs:543-548`), and the bridge copies those raw flags into `PlanRequest` (`src/convert/pipeline/plan_bridge.rs:146-154`). WAV, RF64, and W64 are distinct TUI choices even though the planner format is WAV (`src/convert/formats.rs:244-259`). Native Reference/Manual planning therefore requires a typed resolved codec+container fact; it must not infer policy from arbitrary flag strings. `PlanRequest` gains `resolved_output_target: Option<ResolvedOutputTarget>` during the compatibility period: native DSD routes require `Some`, while old routes may continue to consume the existing extension/flag fields until their own migration.
+
+Independent files selected as one folder/album conversion already receive a shared `AlbumBatchContext` carrying a fresh per-attempt batch ID, expected member count, grouping root, and exact source paths (`src/convert/pipeline/types.rs:120-176`). The dispatcher forms those groups before worker submission and refuses mixed settings/lifecycle policy (`src/convert/processor.rs:300-380`, `src/convert/processor.rs:406-427`), but its grouping key is deliberately folder/output-oriented rather than itself proving one mastering programme (`src/convert/processor.rs:331-357`). That existing contract is useful scheduling and stale-run authority, not sufficient semantic authority for shared gain. Round 2 derives a separate immutable Reference programme contract at dispatch; a track worker must never infer or revise programme membership from tags.
+
+CUE materialization currently creates per-track PCM carriers before the planner, and SACD materialization creates one `PreparedTrack` per TOC track (`src/convert/pipeline/materializer_cue.rs:166-241`, `src/convert/pipeline/materializer_sacd.rs:67-113`). SACD realization then extracts each track separately to DSF/DFF before conversion (`src/convert/pipeline/stages.rs:2045-2112`). That order cannot preserve reconstruction, resampler, or dither state across boundaries and motivates the explicit two-phase implementation.

+## 1.1 Public settings layout
+

+`ResolvedOutputTarget` is an exact codec+container product key, not user-authored serde inside `DsdSettings`. Its variants correspond to the currently enabled `(AudioFormat, ContainerOption)` pairs (`src/convert/formats.rs:244-345`); the trusted request bridge derives one variant exactly once from the requested format, selected container entry, validated extension, and canonical flag sequence. This avoids collisions such as AAC/M4A versus ALAC/M4A and WAV/RIFF versus WAV/RF64, which cannot be distinguished by extension alone. Native DSD routes accept only the subset explicitly defined by their policy or workflow schema. Raw `container_ffmpeg_flags` must be empty or exactly the legacy representation of the resolved variant; conflicting, duplicate, extra, or unrecognized flags fail before planning. During the compatibility period, the pure `PlanRequest` carries `resolved_output_target: Option<ResolvedOutputTarget>`; native Reference/Manual planning requires `Some(target)` and immediately validates the allowed subset, while existing non-native routes may retain `None` and the old raw fields until separately migrated. All native validation, command assembly, preset serialization, behavior identity, and output-path validation use the resolved enum, never the raw fields.
+

+The policy registry, not user settings, owns these Reference constants:
+
+```text
+processing headroom          12.000000000 dB
+requested DSD compensation    6.020599913 dB
+true-peak ceiling            -1.000000000 dBTP
+sinc requested attenuation  180 dB
+sinc phase                    linear
+analyzer report resolution      0.010000000 dB (pinned by accepted FFmpeg output)
+analyzer upper-error bound       qualification-manifest value
+terminal realization bound          conservative linear peak-error bound plus derived safe pre-terminal ceiling, frozen per cell
+no fixed-dB terminal guard                 terminal error is bounded only in linear full-scale amplitude
+float terminal bound                    never assumed zero; each Float32/Float64 candidate must have a defensible linear error bound before the policy is minted
+```
+
+This prevents a user-tunable value from continuing to carry the `Reference` label after it leaves the qualified policy.
+
+### Fixed-point dB representation
+
+Native-v2 settings, policy constants, parsed analyzer values, serialized plans, equality, hashing, arithmetic, and argv rendering all use signed integer nanodecibels (`DbNano`). New serialized settings use canonical signed decimal strings with exactly nine fractional digits; CLI and TUI text entry parse decimal ASCII directly into `DbNano` with checked range and no binary-float round trip. The current DSD gain/margin settings are `f32` (`tonepoet-pipeline/src/settings.rs:731-741`), but those values remain in the private legacy snapshot so compatibility argv can preserve current formatting/semantics. An explicit migration into native-v2 settings displays the legacy value and converts the user's accepted decimal representation to `DbNano`.
+
+Under the policy-pinned `loudnorm` JSON grammar, `input_tp` must be a decimal string or the exact silence literal. The strict parser converts it directly to `DbNano` or to a distinct verified-silence value; it never passes through `f32`/`f64`. Certified one-sided analyzer reporting uncertainty, analyzer error, the policy-derived safe pre-terminal ceiling, requested gain, and applied gain are therefore checked integer arithmetic. Logarithmic derivation from the terminal linear bound is performed offline by the policy generator and conservatively rounded, not recomputed with platform floating point at runtime. This preserves the +6.020599913 dB convention exactly and removes NaN, locale, platform-formatting, and rounding-direction ambiguity from plan identity and ceiling enforcement.
+
+## 1.2 Reference policy registry
+
+A private, table-driven registry maps each `DsdReferencePolicyVersion` to immutable policy data:
+
+```text
+policy id
+qualified decoder/DSP toolchain-closure identity
+qualified true-peak analyzer toolchain-closure identity and parser contract
+accepted source container/encoding/rates/channel counts
+headroom dB
+compensation dB
+ceiling dBTP
+requested sinc attenuation
+profile definitions
+supported target rates/depths/formats
+certified analyzer one-sided reporting uncertainty per cell
+terminal linear peak-error bound and derived safe pre-terminal ceiling per target-rate/depth cell
+qualification evidence digest per matrix cell
+```
+
+The first ID is serialized as `sox_ng_14_8_0_1_v1`. Policy IDs are append-only and immutable. Changing a coefficient, route, gain rule, supported matrix cell, analyzer contract, toolchain closure, terminal bound, or quantization rule requires a new policy ID. A feature flag, build option, environment variable, downloaded table, or mutable qualification file must never enable a cell under an already serialized ID. The release containing v1 therefore freezes one support matrix; later evidence produces `..._v2` or a separately named policy.
+
+The policy qualification manifest is generated and signed or content-addressed by the build/package process. It is evidence attached to an immutable policy, not a runtime toggle. It identifies the complete qualified toolchain closure: executable bytes plus every dynamically loaded library, plugin, codec module, and policy-owned resource that can affect output. On Nix/Flox builds this should be a store-closure/NAR identity; other packaging must provide an equivalently reproducible closure manifest. A platform that cannot attest the qualified closure does not expose Reference under that policy.
+
+At preflight, the orchestrator—not the pure planner—resolves the executable from the configured tool identity, validates the immutable closure identity, checks the executable content digest and exact reported version, and runs the policy's behavior probes. SoX must report 14.8.0.1 exactly or the packaging identity must bind the pinned evidence commit. The true-peak analyzer is equally policy-owned: its accepted FFmpeg build/closure identity, exact analysis argv, parser grammar, report rounding model, certified one-sided reporting uncertainty, and inter-sample-peak fixture digest are frozen in the policy. Any mismatch is a preflight error. Manual workflows may use other installed versions, but record the observed identity and receive an unqualified-backend warning.
+
+This identity is a conservative compatibility contract under a trusted local package/store boundary; it is not a claim that tonepoet can defeat a privileged actor replacing mapped executable or library bytes concurrently with execution. Reference requires immutable package-store semantics or equivalent operating-system guarantees. Otherwise it fails closed.
+

+## 1.4 Validation rules
+
+Validation occurs before plan construction and is deterministic.
+
+### Reference pathway
+
+Reference requires:
+
+- `audio_workflow == None`;
+- source kind is native uncompressed DSF or uncompressed DSDIFF;
+- source rate is DSD64, DSD128, or DSD256;
+- source channel count is known, is one or two, and that container/rate/channel-count cell is frozen as supported by the selected immutable policy;
+- target is PCM-lossless and resolves to one exact Reference-supported `ResolvedOutputTarget` variant; arbitrary container flags and native-DSD targets outside the frozen Reference subset are forbidden;
+- target rate is one of 44,100; 48,000; 88,200; 96,000; 176,400; 192,000; 352,800; 384,000; 705,600; 768,000 Hz and is frozen as supported by the selected immutable policy;
+- resolved depth is Int16, Int24, Float32, or Float64 and is legal for the requested target/container under the §3.8 format/depth matrix; RIFF/WAV also passes the deterministic preflight size bound, and WavPack is lossless non-hybrid;
+- `fixed_gain_db` is `Some` and within −24.000000000 to +24.000000000 dB only when `gain_mode == Fixed`;
+- `fixed_gain_db == None` for other gain modes;
+- `normalize_peak_target_dbfs` is in −12.000000000 to 0.000000000 dBFS;
+- Wideband is legal for the source/target pair under the selected immutable policy. B6 and every other unavailable cell remain hard rejections under v1 regardless of local build/test state.
+
+`BitDepthTarget::Source` continues to resolve a DSD source to the target format's documented default, currently 24-bit for PCM-lossless formats (`tonepoet-pipeline/src/plan.rs:1543-1585`, `tonepoet-pipeline/src/settings.rs:936-943`).
+
+### Manual pathway
+
+Manual requires:
+
+- `audio_workflow == Some(snapshot)`;
+- snapshot schema version is supported and its custom parser has rejected duplicate, mixed-version, and unknown fields;
+- every dependency object exists in the tonepoet-owned content store and matches its recorded size/hash;
+- at least one stage;
+- unique stage IDs;
+- each stage has exactly one `{input}` and one `{output}` token and references only declared dependency IDs;
+- only the `sox`, `ffmpeg`, and `ssrc` backends;
+- no shell executable, shell expression, response file, user-provided working directory, literal auxiliary path, alternate primary output, undeclared network/device endpoint, or known secondary-output mode;
+- every auxiliary file is a declared `{dependency:ID}`;
+- `output_extension` is the canonical extension for the declared container+codec pair and contains no path separator;
+- intermediate stages declare a format accepted by the probe layer and have `resolved_target == None`;
+- the final stage has `resolved_target == Some(requested_target)` and declares `sample_rate_hz`, `sample_format`, and `channels`; its container+codec+extension triple must be the canonical physical representation of that exact target, its rate/channels equal the resolved target contract, and its concrete lossless/PCM sample format equals the resolved target sample kind/depth (lossy and DSD/DST use `Encoded`);
+- every unclassified backend option is rejected unless `unclassified_option_policy == TrustedUnsandboxed`, in which case it is preserved literally, logged with a stable warning, and treated as trusted local code outside tonepoet's side-effect-confinement guarantee;
+- the snapshot's recomputed canonical hash equals `canonical_sha256`.
+
+DSP lint findings do not make the workflow invalid unless they reveal an execution-ownership violation or an internally contradictory declared output contract.
+
+## 1.5 Fate of current DSD types
+
+- `DsdLowpassMethod` is removed from the new public settings model. Its Auto/SoxUltra distinction has no useful Reference meaning, and its Sinc arm becomes expressible as an explicit Manual SoX stage.
+- `SincFilterSettings` is renamed `PcmToDsdSincSettings` and remains only under `PcmToDsdSettings`.
+- The old `DsdToPcmGainMode::{Disabled, Auto, Manual}` enum is replaced by `DsdSourceGainMode` and its four new semantic names. Old serialized values are migrated as specified in §8.
+- `DsdRate::default_pcm_lowpass_hz` is removed. A single cutoff cannot represent a profile and its DSD128/DSD256 values encode superseded policy; the current function is at `tonepoet-pipeline/src/enums.rs:332-349`.
+- `DsdRate::default_pcm_target_hz` remains for Source target resolution for DSD64/128/256. Its DSD512/1024 values may remain for Manual mode, but Reference routing validates the source backend before using them; current defaults are at `tonepoet-pipeline/src/enums.rs:320-330`.
+
+## 1.6 Serde strategy
+
+### New files
+
+All persisted new enums use explicit snake-case names rather than Rust discriminants. The settings values include `reference`, `manual`, `sox_ng_14_8_0_1_v1`, `wideband`, `native_level`, `fixed`, and `normalize_peak`; workflow authority values include `reject`, `split_then_process_acknowledged`, and `trusted_unsandboxed`. Workflow container/codec/sample/quantization/dither enums likewise use their exact lower-snake-case spellings. `ResolvedOutputTarget` is not settings serde, but its workflow/preset/manifest/hash key is the frozen lower-snake-case spelling of its variant (for example `wav_rf64` or `alac_m4a`). Unknown spellings are errors, not aliases.
+
+`PipelineSettings.audio_workflow` uses `#[serde(default, skip_serializing_if = "Option::is_none")]`.
+
+### Existing persisted `PipelineSettings`
+
+`DsdSettings` uses a hand-written map serializer/deserializer, not `#[serde(untagged)]`. The current flat structure mixes six PCM→DSD fields with four DSD→PCM fields (`tonepoet-pipeline/src/settings.rs:716-745`), and an untagged/defaulted representation could accept ambiguous mixed forms or swallow misspelled keys. The parser therefore records every key, rejects duplicate and unknown keys, then selects exactly one wire form:
+
+1. **Native v2:** requires `schema_version = 2`, `pcm_to_dsd`, and `from_dsd`; accepts only the exact native-v2 key set.
+2. **Legacy flat v1:** has no schema tag and accepts only the exact current flat key set shown by the current ten-field structure (`tonepoet-pipeline/src/settings.rs:720-745`).
+
+The native wire shape is exact rather than inferred from the in-memory type:
+
+```rust
+pub struct DsdSettingsWireV2 {
+    pub schema_version: u32, // exactly 2
+    pub pcm_to_dsd: PcmToDsdSettings,
+    pub from_dsd: DsdSourceSettings,
+}
+```
+
+A map containing both native and legacy keys, a native map without `schema_version = 2`, or any unknown key is an error. `origin` is private in-memory state and is never accepted as a user-authored wire key.
+
+The compatibility parser maps the legacy fields without loss:
+
+| Legacy field | Native-v2 destination or preserved compatibility interpretation |
+|---|---|
+| `noise_shaper` | `pcm_to_dsd.noise_shaper` |
+| `modulator_order` | `pcm_to_dsd.modulator_order` |
+| `trellis` | `pcm_to_dsd.trellis` |
+| `pcm_to_dsd_filter` | `pcm_to_dsd.filter` |
+| `gain_compensation` | `pcm_to_dsd.gain_compensation` |
+| `sinc` | `pcm_to_dsd.sinc`, and copied verbatim into the private legacy DSD→PCM snapshot because the current Sinc arm consumes the same field (`tonepoet-pipeline/src/plugins.rs:1622-1639`) |
+| `dsd_to_pcm_lowpass = Auto` or `SoxUltra` | execute the old post-rate single-cutoff behavior; show `Legacy SoX lowpass (preserved)`, not `Reference` |
+| `dsd_to_pcm_lowpass = Sinc` | execute the old pre-rate custom-sinc behavior; show `Legacy custom sinc (preserved)` |
+| gain `Disabled`, no stray dB | execute no gain; show `Legacy native level` |
+| gain `Disabled`, stray dB present | execute the compatibility fixed gain; show `Legacy fixed gain` |
+| gain `Auto` | execute old SoX peak normalization using `old_margin`; show `Legacy normalize` |
+| gain `Manual` | execute old fixed gain using the old value; show `Legacy fixed gain` |
+
+The exact private compatibility payload is the complete old wire object, not only the DSD→PCM subset:
+
+```rust
+pub struct LegacyDsdSettingsWireV1 {
+    pub noise_shaper: DsdNoiseShaper,
+    pub modulator_order: ModulatorOrder,
+    pub trellis: Option<TrellisSettings>,
+    pub pcm_to_dsd_filter: DsdFilterPreset,
+    pub dsd_to_pcm_lowpass: DsdLowpassMethod,
+    pub dsd_to_pcm_gain_mode: LegacyDsdToPcmGainMode,
+    pub dsd_to_pcm_auto_gain_margin_db: f32,
+    pub dsd_to_pcm_gain_db: Option<f32>,
+    pub sinc: SincFilterSettings,
+    pub gain_compensation: GainCompensation,
+}
+```
+
+Deserializing the legacy form stores `DsdSettingsOrigin::LegacyFlatV1(original_wire)` and mirrors the six PCM→DSD values into the new public substructure. While that origin is present, planning derives a private DSD→PCM compatibility view from `original_wire` and emits the old argv exactly, including the old pre-rate custom-Sinc arm. Serializing a legacy item first proves that every mirrored legacy-representable PCM→DSD field still equals `original_wire`; if any has diverged, serialization fails with an explicit migrate-first error rather than collapsing two meanings back into the old shared `sinc` key. An unchanged legacy item emits the same legacy flat **shape and values** again and does **not** write a hidden compatibility key. This is semantic round-trip compatibility, not preservation of the original JSON/TOML byte spelling: the current `f32` wire types already discard lexical distinctions such as exponent form or redundant zeros at parse time. A native item emits only the tagged v2 form.
+
+The edit surface remains visibly legacy and offers explicit migration to native Reference settings or generation of a Manual workflow. Opening or saving unrelated non-DSD fields does not migrate it. Any DSD-field edit, including PCM→DSD `sinc`, requires an explicit migration because the old flat wire cannot represent independent directional values. Reconfiguration changes the origin to `NativeV2` only after the user accepts the output-changing migration. New conversions and old TUI presets that never contained full DSD settings use the new Reference default. Thus queued work round-trips without acquiring new semantics, the old dual-use field cannot silently diverge, and private compatibility state cannot be forged by configuration input.
+
+### Workflow snapshot serde
+
+The queue stores the full normalized workflow snapshot, not merely a name or path. A named/path selection is resolved before queue admission. This keeps queued work independent of later edits to a workflow file and fits the existing persisted full-settings invariant (`src/convert/queue.rs:198-203`, `src/convert/formats.rs:605-612`).
+
+## 1.7 Fingerprints
+
+The current `settings_fingerprint` is a version-1, conversion-affecting, mode-scoped hash; it is not a byte-for-byte hash of every serialized setting. It conditionally hashes fields such as DSD gain and resampler choices (`tonepoet-pipeline/src/fingerprint.rs:55-115`, `tonepoet-pipeline/src/fingerprint.rs:182-205`, `tonepoet-pipeline/src/fingerprint.rs:320-375`). Existing manifests persist that value and the rerun gate treats it as authority (`src/convert/pipeline/manifest.rs:15-22`, `src/convert/pipeline/manifest.rs:45-54`, `src/convert/pipeline/rerun.rs:154-182`). Its algorithm and domain must therefore remain byte-for-byte available for legacy compatibility.
+
+Introduce explicitly versioned identities rather than silently changing the existing function:
+
+```rust
+pub fn legacy_settings_fingerprint_v1(
+    settings: &LegacyCompatiblePipelineSettings,
+) -> LegacySettingsFingerprintV1;
+
+pub fn settings_snapshot_fingerprint_v2(
+    settings: &PipelineSettings,
+) -> SettingsSnapshotFingerprintV2;
+
+pub fn conversion_behavior_fingerprint_v1(
+    settings: &PipelineSettings,
+    source: &SourceInfo,
+    resolved_plan: &ConversionPlan,
+) -> BehaviorFingerprintV1;
+```
+
+`legacy_settings_fingerprint_v1` is the current algorithm under its current domain and field ordering (`tonepoet-pipeline/src/fingerprint.rs:139-145`), retained behind regression fixtures and the existing sentinel. `settings_snapshot_fingerprint_v2` hashes the canonical native-v2 wire representation, including every serialized behavior and provenance field that the schema declares fingerprint-bearing. `conversion_behavior_fingerprint_v1` is source-aware and hashes only the fields and resolved policy/plan decisions that can affect bytes or acceptance. The two native identities are intentionally distinct: a display/provenance edit may change the snapshot without changing audio behavior.
+
+Plan hashing must be independent of ephemeral allocation paths. Before hashing, every planner-owned path is replaced by a typed role:
+
+```text
+{SOURCE:n}
+{FINAL:n}
+{WORK:n}
+{DEPENDENCY:<sha256>}
+```
+
+The semantic plan hash covers operation kinds, canonical argv tokens with path roles, environment, source facts, profile, policy, programme scope, measurement parsers, deferred binding expressions, output contracts, and finalization semantics. Raw resolved argv and absolute paths remain in the execution transcript but do not destabilize cross-run semantic identity. Source content/path identity and output facts remain separate rerun inputs.
+
+Settings/plan behavior still does not identify the implementation that produced bytes. Add an execution identity constructed by the orchestrator after pure planning and before rerun admission:
+
+```rust
+pub struct ExecutionFingerprintV1(pub Sha256Digest);
+
+pub struct ResolvedToolIdentity {
+    pub tool: ToolIdentifier,
+    pub canonical_executable: PathBuf,
+    pub executable_sha256: Sha256Digest,
+    pub reported_version: String,
+    pub toolchain_closure_digest: Option<Sha256Digest>,
+    pub behavior_probe_digest: Option<Sha256Digest>,
+    pub platform_abi: String,
+    pub runtime_dispatch_digest: Sha256Digest,
+}
+```
+
+The execution fingerprint hashes a domain/version tag, behavior fingerprint, semantic plan hash, planner/build identity, immutable policy ID, qualification-manifest digest, platform/ABI, effective CPU/SIMD runtime-dispatch identity, each resolved external toolchain identity in first-use order, and every in-process backend build identity. Reference admission requires both optional digests to be `Some` and to match the immutable qualification manifest. Manual admission may record `None` when the installation has no package-closure or behavior-probe authority; presence/absence and values are still hashed and logged, and Manual remains explicitly unqualified. The current runner already resolves configured/PATH executables and maintains a shared version cache (`src/convert/pipeline/tool.rs:315-358`), while provenance currently derives versions after command records exist (`src/convert/pipeline/stages.rs:15627-15665`). Native-v2 admission moves resolution and attestation into an orchestrator preflight phase. It validates executable content/version and, where required, closure identity and behavior probes immediately before rerun admission and again before launch to the extent supported by the package/store boundary. A mismatch aborts rather than running under a stale recorded identity. Output-affecting environment variables, locale, thread/dispatch controls, and package-relative resource roots are normalized by policy or included in the dispatch digest; Reference qualification must reject an uncontrolled runtime dispatch path.
+
+Manifest schema v2 is version-dispatched before deserializing its settings payload and has exact route-level and per-track identity placement. It does not impose native-DSD execution fields on unrelated conversion paths, and it does not put a source-aware plan identity in an album-wide field:
+
+```rust

+}
+
+pub struct ConversionManifestTrackV2 {

+
+The v2 parser rejects a route/track variant mismatch, duplicate or unknown fields, `total_tracks`/length disagreement, a native track whose behavior target disagrees with the route-level `resolved_output_target`, a programme identity on a legacy or Manual route, a native Reference programme whose ordered membership does not exactly match its track entries, and a native DSD track without both a full source-content SHA-256 and a full output SHA-256. `settings` is retained for audit and explicit reconfiguration, but reuse never trusts its presence or reserializes it to invent an identity.
+
+New Reference writes `DsdReferenceV2` plus per-track `NativeDsdV2`; new Manual writes `DsdManualV2` plus per-track `NativeDsdV2`. Both native route variants bind the exact resolved codec+container target because that fact intentionally lives outside `PipelineSettings`. Existing PCM→PCM, PCM→DSD, and private legacy-compatible DSD→PCM routes may write a v2 envelope only with matching `LegacyPipelineV1` route and track variants, preserving the exact old applicable-field fingerprint/planner-command authority. An on-disk manifest-v1 record is parsed through its frozen v1 struct and may be represented as legacy identity in memory, but it is not rewritten merely by inspection.
+
+A native DSD skip requires matching route identity, per-track behavior/execution/semantic-plan identities, required source-content identity, source facts, required output hash/size, and—when present—the exact programme identity and membership. A legacy identity may skip only through the unchanged v1 fingerprint algorithm with settings still representable in the old schema and all existing source/output checks. For DSD→PCM, that specifically requires `DsdSettingsOrigin::LegacyFlatV1`; code must never infer native-v2 equivalence from a legacy manifest or recompute a v1 hash from migrated native settings.
+
+Native behavior identity is pathway-scoped rather than hashing inactive controls:
+
+```text
+always:
+  dsd.from_dsd.pathway
+  target format/rate/depth and exact `ResolvedOutputTarget` codec+container key
+  resolved output-byte-affecting package/encoder settings
+  metadata/verification settings that alter bytes or acceptance
+
+Reference only:
+  dsd.from_dsd.reference_policy
+  dsd.from_dsd.profile
+  dsd.from_dsd.gain_mode
+  dsd.from_dsd.fixed_gain_db when Fixed
+  dsd.from_dsd.normalize_peak_target_dbfs when NormalizePeak
+  resolved programme grouping rule and deterministic membership when applicable
+
+Manual only:
+  audio_workflow.schema_version
+  normalized audio_workflow execution digest
+  every declared stage output contract and dependency content identity
+```
+
+`DsdSettingsOrigin` is not a native behavior field: the manifest route/track variants already separate legacy from native domains, and native-v2 wire data never serializes the private origin. Inactive Reference controls may change the settings-snapshot hash for audit but cannot invalidate Manual execution equivalence; likewise workflow display name/source paths and an inactive workflow cannot invalidate Reference behavior.
+
+Rules:
+
+- Hash canonical enum/string encodings, never Rust discriminants.
+- Hash no derived Reference constant individually; the immutable policy ID and qualification digest own them.
+- Hash the normalized workflow execution digest, not its display name or source path.
+- Reference and Manual do not hash generic resampler/dither controls that their planner firewall cannot consume.
+- PCM→PCM, PCM→DSD, and legacy-compatible DSD→PCM preserve their current applicable-field behavior under the retained v1 algorithm until separately migrated.
+- Legacy, Reference-v2, and Manual-v2 occupy distinct route domains and cannot cross-match.
+- Programme attempt IDs and random staging paths are excluded; deterministic programme membership/content identities are included.
+
+Tests lock the old v1 hash fixtures, native-v2 canonical serialization, semantic path-role normalization, mode-scoped inclusion/exclusion, programme membership, tool/closure drift, and manifest-version dispatch.

+
+## 2.1 Source-fact extension
+
+Add to `SourceInfo` with backward-compatible serde defaulting, because `SourceInfo` itself is serialized when the crate's serde feature is enabled (`tonepoet-pipeline/src/source.rs:31-62`):
+
+```rust
+#[cfg_attr(feature = "serde", serde(default))]
+pub dsd_source_kind: Option<DsdSourceKind>
+
+pub enum DsdSourceKind {
+    DsfUncompressed,
+    DsdiffUncompressed,
+    DsdiffDst,
+    SacdArea { frame_format: SacdFrameEncoding },
+    UnknownDsdContainer,
+}

+## 2.2 Planning, preflight, and execution steps
+
+The pure `tonepoet-pipeline` planner remains deterministic, serializable, and free of filesystem/process I/O. `PlanAction::Execute.commands` becomes `steps: Vec<PlannedExecutionStep>`; the current action stores a static command vector (`tonepoet-pipeline/src/plan.rs:298-327`). Planning and runtime authority are explicitly phased:
+
+```text
+stable source-content identity and probe facts
+  → pure plan with required ToolIdentifier values and typed path roles
+  → orchestrator toolchain resolution/attestation and behavior probes
+  → execution fingerprint
+  → rerun decision
+  → when execution is required, verified non-hard-linked source materialization
+  → execution
+```
+
+Illustrative source authority:
+
+```rust
+pub struct SourceContentIdentity {
+    pub size_bytes: u64,
+    pub sha256: Sha256Digest,
+    pub probe_digest: Sha256Digest,
+}
+
+pub struct PreparedSourceMaterialization {
+    pub original_path: PathBuf, // provenance only
+    pub work_path: PathBuf,
+    pub identity: SourceContentIdentity,
+}
+```
+
+Native-v2 admission opens the user-selected path once under ordinary input semantics (a symlink may resolve), records both the presented and resolved paths, requires the resulting handle to be a regular file, and obtains content identity plus probe facts from that handle with pre/post identity and metadata checks. A rerun hit needs no work copy. On a miss, execution reopens/resolves the source if necessary, requires the admitted identity/content hash again, then copy-on-write clones or copies from the verified handle—never hard-links—into the work root, hashes/probes the materialization, and requires an exact match before any backend starts. Reference and Manual commands receive only `work_path`; the original path is provenance. Detected source mutation fails closed rather than allowing a fingerprint to authorize different bytes. This is ordinary same-user race protection, not a claim to defeat a malicious privileged writer or a filesystem that violates its documented clone/copy semantics.
+
+Illustrative execution-step shape:
+
+```rust

+```
+

Ambiguous album/disc identity, incomplete membership, or two releases sharing a folder rejects multi-member Reference instead of silently sharing gain. The authority validates the contract plus identical Reference behavior fingerprints and releases one maximum only after every expected member renders and measures successfully; all-silent handling requires every member's independent zero-sample proof.

+## 2.4 Reference route
+
+The system performs these phases in order:
+
+1. Source identity/probing obtains stable content identity and classifies container, encoding, rate, channels, and programme scope from the same bytes.
+2. The pure planner resolves target rate/depth/container, immutable policy cell, profile, gain semantics, semantic path roles, measurement/deferred steps, packaging, verification, and cleanup. It rejects undefined or unsupported cells without consulting runtime state.
+3. The orchestrator resolves and attests every required toolchain closure, verifies policy behavior probes, computes the execution fingerprint, and only then evaluates rerun reuse.
+4. On a rerun miss, execution first creates and verifies the non-hard-linked source materialization against the admitted identity; it then renders, measures, resolves the authorized constant gain, performs exactly one terminal realization, measures the final PCM, packages sample-preservingly, verifies, and publishes.
+
+Reference rejects lossy/non-PCM targets, every `ResolvedOutputTarget` outside `FlacNative | WavRiff | WavRf64 | WavW64 | AiffNative | WavPackNative | AlacM4a`, and any unresolved/custom container flag sequence. The exact target key is authoritative for direct W64 versus RIFF/RF64 packaging; output-path extension is validated against it but never used as the sole semantic discriminator. For `Reference`, post-final true peak must not exceed −1.000000000 dBTP. `NativeLevel` and `Fixed` preserve their exact requested gain and fail before publication when the policy's conservative pre-final bound cannot satisfy the same ceiling; they are never silently reduced. `NormalizePeak` is a modified legacy-compatible semantic: it records post-final true peak but is not accepted or relabeled under the Reference −1 dBTP contract.
+
+### Gain/profile qualification wording
+
+- The full standard Reference label requires pathway `Reference`, profile `Reference`, gain mode `Reference`, and a cell/toolchain frozen as qualified by the selected policy.
+- `NativeLevel` and `Fixed` may retain a qualified Reference reconstruction front-end but are explicitly labeled modified exact-gain paths.
+- `NormalizePeak` is labeled modified/unqualified gain behavior.
+- B4W and any future B6-capable policy use explicit Wideband/provisional wording; they never inherit the standard full Reference label merely because gain mode is `Reference`.
+- Float output still emits the one constant gain stage but no integer quantization or dither.
+
+### Tool identity
+
+Reference never falls back to FFmpeg decoding, a different SoX build, sample-peak analysis, or an unattested analyzer. Tool resolution and attestation occur outside the pure planner and before rerun admission. Manual workflows run only their selected built-in backends, include observed identities in the execution fingerprint, and are invalidated for reuse when those identities change.
+

+## 2.6 Programme authority and continuous programmes
+
+### Programme classification
+
+Before worker submission, source expansion assigns:
+
+```rust
+pub enum ReferenceProgrammeScope {
+    Singleton,
+    IndependentAlbumBatch {
+        contract: ReferenceProgrammeContract,
+    },
+    ContinuousImageRequiresPreSplitProcessing,
+}
+```
+
+A standalone file is a singleton only when no dispatcher-authored multi-member batch claims it. An `AlbumBatchContext` with more than one member is therefore sufficient to prevent worker-side singleton downgrade, but Round 2 does not share gain until dispatch has also minted the gain-specific `ReferenceProgrammeContract`. The current transport contract carries the per-attempt ID, expected count, grouping root, and exact source paths (`src/convert/pipeline/types.rs:120-176`). The programme digest is computed from the policy-owned grouping rule, semantic programme identity, exact ordered membership, canonical source identities, and immutable admission-time content identities, never from mutable tags alone. Where a content digest is unavailable at dispatch, admission computes it before Reference work begins rather than relying on size/mtime alone.
+
+### Round-1 guard
+
+Round 1 supports Reference-front-end processing only for `Singleton`. It rejects every multi-member `IndependentAlbumBatch`, because independent measurement would create track-varying gain or acceptance decisions, and rejects every `ContinuousImageRequiresPreSplitProcessing`, because conversion after splitting resets reconstruction/filter/dither state.
+
+That continuity guard is independent of gain mode. `NormalizePeak` may run per track only for genuinely independent files when the user explicitly chooses programme-dependent normalization; it does not authorize pre-split processing of a continuous CUE/SACD image. Manual schema v1 rejects continuous images by default. It permits split-first, per-track execution only when `continuous_source_handling == SplitThenProcessAcknowledged`; the log records the explicit discontinuity acknowledgement. Schema v1 does not claim a whole-programme Manual workflow followed by track splitting—adding that requires a later schema with an explicit programme-output/split contract.
+
+### Round-2 stable seam
+
+For independent album batches, the programme measurement authority in §2.2 permits parallel render/measurement, computes one maximum true peak, then releases the same applied gain to every member. Round 2 places an all-members verification/release gate in front of the existing whole-album sibling-directory publisher (`src/convert/pipeline/stages.rs:19077-19276`): all members must pass post-final verification before the publisher receives any native-v2 entry. The complete album and mandatory manifest are staged on the destination filesystem, files/directories are durability-synced, and a previously absent final album directory is published by one non-replacing directory rename followed by parent-directory sync. Reference refuses merge/overwrite into an existing final album directory until a separately tested journaled swap/recovery protocol prevents mixed old/new member sets after process or host failure. Failure or cancellation before commit publishes nothing.
+
+For continuous CUE/SACD sources, the materializer gains a programme-level product:
+
+```rust
+PreparedProgramme {
+    continuous_source,
+    boundaries: Vec<ProgrammeBoundary>,
+    source_audio,
+    metadata,
+}
+
+pub struct ProgrammeBoundary {
+    pub source_ticks: u64,
+    pub ticks_per_second: NonZeroU32,
+}
+```
+
+The programme is reconstructed, resampled, filtered, measured, gain-restored, and quantized once. A sample-preserving splitter then creates track carriers. Boundaries use an exact source timebase (for example CUE frames at 75 ticks/s or native DSD sample frames), not binary floating-point seconds. Mapping is cumulative, never independently rounded per track: policy qualification pins `output_frame_count(prefix_ticks, ticks_per_second, target_rate)` to the exact whole-programme decoder/SoX duration and delay-compensation behavior, and each target boundary evaluates that function at the source prefix. The first boundary is zero; the last must equal the actual quantized programme frame count; interior boundaries must be strictly increasing and within range. Duplicate or zero-length mapped tracks fail closed. Tracks are half-open intervals `[b_i, b_{i+1})`, so no sample is duplicated or omitted. If decoder delay, resampler delay, or frame-count mapping cannot be proven for a source/backend cell, that continuous cell remains unavailable.
+
+For CUE, the source is the original image rather than one WAV per index range. For SACD, the selected area must be extracted/decoded as one continuous DSD programme. If the extraction layer cannot provide that contract, SACD continuous Reference remains unavailable. Qualification fixtures cover fractional-ratio boundaries, CUE/SACD timebases, rejected duplicate/zero-length mappings, high DSD rates, total duration, and bit-identical split/rejoin. Boundary lists and their exact timebases are included in the programme digest and semantic plan hash.
+
+## 2.7 Cleanup, cancellation, and publication
+
+All source materialization, render, measurement, workflow, quantized-PCM, package, metadata, verification, journal, and per-run dependency paths are planner-declared cleanup paths. The new pathways integrate with the existing authority-bound album publisher described in §0.2; they do not bypass it through the low-level track executor.
+
+Two publication cases are distinct:
+
+### Whole-album / absent-destination transaction
+
+When all outputs for an absent album directory are available together, reuse the existing sibling-directory assembly and one-rename publication path (`src/convert/pipeline/stages.rs:19077-19276`) with these native-v2 hardening requirements:
+
+1. No member enters publication until every required member has completed metadata mutation, decoded-sample verification, post-final peak acceptance, and output hashing.
+2. Every staged file and the assembled temporary directory are durability-synced before rename; sync failures are fatal, not best-effort warnings.
+3. The complete v2 manifest is written inside the temporary album directory and is mandatory. The current nonfatal behavior (`src/convert/pipeline/stages.rs:19239-19253`) is forbidden for Reference/Manual native-v2 publication.
+4. The retained publication authority revalidates destination absence immediately before the one non-replacing directory rename. An unexpected destination fails closed.
+5. The destination parent is synchronously persisted after rename. A failure leaves an explicit recoverable-published state rather than pretending that no publication occurred.
+6. Backup/replace of an existing album remains outside the initial programme Reference policy; §9 Q7 governs that later capability.
+
+Because audio files and their manifest are inside one renamed directory, this is the preferred native-v2 commit boundary and already matches the strongest shape in the current publisher.
+
+### Incremental existing-directory file transaction
+
+A singleton Reference output or Manual output may target an existing album directory only through a new capability integrated under the same retained album publication authority and lock as the existing incremental path. The current incremental code has rollback machinery but installs entries and then writes the shared album manifest nonfatally (`src/convert/pipeline/stages.rs:19347-20079`), so native-v2 adds an explicit journaled transaction:
+
+```rust
+pub struct IncrementalFilePublicationTransaction {
+    pub album_dir: PathBuf,
+    pub destination: PathBuf,
+    pub staged_file: PathBuf,
+    pub expected_prior_destination: ExpectedPathIdentity,
+    pub previous_manifest_hash: Option<Sha256Digest>,
+    pub next_manifest_payload: ConversionManifestV2,
+    pub next_manifest_hash: Sha256Digest,
+    pub staged_output_hash: Sha256Digest,
+}
+```
+
+This incremental capability is intentionally narrow: it admits exactly one native-v2 audio output and no active multi-member programme/batch contract. Multi-member Reference or Manual work must reach the whole-album gate. If the directory already has a manifest, it must be a valid v2 manifest with the identical route identity—including `resolved_output_target`—and settings-snapshot authority; every retained manifest entry/output must still verify before the new complete payload is derived. A v1, corrupt, missing-but-previously-managed, different-route, or different-settings manifest is not merged or replaced implicitly. An existing directory with no tonepoet manifest may receive a new singleton manifest only after authority-bound inventory proves there is no conflicting tonepoet transaction/manifest artifact; unrelated unmanaged files are not claimed by the manifest. Native-v2 never mixes Reference, Manual, or legacy routes in one album manifest.
+
+The transaction:
+
+1. Holds the existing descriptor-bound album publication authority for the entire commit and recovery decision; concurrent file/manifest updates cannot interleave.
+2. Produces, mutates metadata, verifies, hashes, and `fsync`s the complete file at a sibling staging path on the destination filesystem.
+3. Revalidates the destination identity/nonexistence and the current complete manifest hash immediately before commit. Any race or unrecognized manifest state fails.
+4. Writes and `fsync`s a journal containing the exact prior identity, staged hash, previous manifest hash, complete next manifest payload/hash, and monotonic transaction state.
+5. Installs an absent destination with a platform-qualified atomic **no-replace rename primitive**. An explicitly requested overwrite uses a platform-qualified atomic replace primitive; it never removes the old destination first. A platform/filesystem without the required primitive refuses that operation.
+6. Persists the album directory, atomically replaces the shared manifest with the journaled complete next payload, persists the directory again, then marks/removes the journal durably.
+
+The audio name and shared manifest cannot be changed in one universal filesystem primitive, so recovery is part of the authority contract. A crash after file install but before manifest commit verifies the destination against the journal and either completes the exact next manifest or reports `PUBLISHED-WITHOUT-RERUN-AUTHORITY`; it never treats an absent/stale manifest as reuse proof and never silently deletes a verified output. A crash before install preserves the prior destination and prior manifest. Manifest rebuilding by directory inspection is forbidden because it cannot reconstruct execution identity.
+
+Measurement output is in-memory typed data, not a reusable sidecar. Workflow outputs are never trusted because a path exists. A restarted pre-publication conversion resets its work root and reruns all required steps. Cancellation is checked before each process, after each process, before every deferred release, before journal creation, and immediately before the non-cancellable atomic commit primitive. Round 2 adds programme measurement/all-members release authority, but it reuses the hardened whole-album transaction rather than creating a second publication implementation.
+

+## 3.1 Notation and canonical formatting
+
+```text
+IN          verified planner-owned materialization of the admitted native DSF/uncompressed DSDIFF bytes
+R64         deterministic 64-bit-float W64 render carrier
+QPCM        deterministic terminal-PCM W64 carrier
+FINAL       deterministic final container staging file

+All Reference commands use `LC_ALL=C`. Paths are separate argv tokens. No shell is involved. SoX numeric values use decimal ASCII without locale grouping. Every SoX command includes global `-D` to disable SoX's implicit automatic dither; integer finalization then invokes exactly one explicit policy-owned `dither` effect. The implementation must qualify that `-D` suppresses only automatic insertion and does not suppress the explicit effect under the pinned SoX-ng identity. Reference does not use `-R`: provenance is deterministic, but deliberate regeneration of a dithered integer output is not promised bit-identical unless a future policy qualifies a decorrelated deterministic seeding mechanism.

+## 3.4 True-peak measurement
+
+Exact analysis-only argv:
+
+```text
+ffmpeg -nostdin -hide_banner -nostats -loglevel info
+       -i R64
+       -filter:a loudnorm=I=-23.0:LRA=7.0:TP=-1.0:print_format=json
+       -f null -
+```
+
+Single-line tokens:
+
+```text
+["-nostdin", "-hide_banner", "-nostats", "-loglevel", "info",
+ "-i", R64,
+ "-filter:a", "loudnorm=I=-23.0:LRA=7.0:TP=-1.0:print_format=json",
+ "-f", "null", "-"]
+```
+
+The output audio is discarded; only `input_tp` from the analyzer's JSON report is authoritative. Explicit I/LRA/TP values stabilize the invocation but do not authorize applying the filter's output gain.
+
+Parser contract:
+
+- parse exactly one final JSON object emitted by the identified `loudnorm` instance;
+- require exactly one `input_tp` string in dBTP and reject use of `output_tp`;
+- require the policy-pinned decimal grammar/resolution or the literal `-inf`;
+- accept `-inf` only after a deterministic scan of the R64 W64 carrier proves every finite sample is signed zero; reject NaN/Inf samples during that scan;
+- reject NaN, positive infinity, absent/duplicate reports, locale commas, unknown numeric syntax, and values outside −1000 to +100 dBTP;
+- record toolchain identity, raw JSON, reported value, rounding model, and conservative upper-bound value;
+- parse finite values directly into `DbNano`; no binary floating-point value enters policy arithmetic or serialized identity.
+
+The policy stores a certified **one-sided reporting uncertainty** `Q` for the exact analyzer build/grammar. It then derives `E` as the maximum residual positive shortfall of `(TP_reported + Q)` against the qualification reference, so reporting quantization is not double-counted:
+
+```text
+TP_upper = TP_reported + Q + E
+```
+
+`Q = 0.005000000 dB` is permitted only when qualification proves round-to-nearest at 0.01 dB. If the tool truncates, rounds directionally, or the rule is uncertain, `Q` is the full one-sided worst case (at least 0.010000000 dB for a 0.01 dB report step) or the cell remains unavailable. The parser never infers `Q` from the number of printed decimals.
+
+A finite fixture corpus cannot by itself prove a universal analyzer error bound. `E` must be justified by a standards-conformance tolerance, implementation/filter analysis, or another defensible one-sided contract, with the tool-gated corpus validating that contract. Without such a basis, the cell cannot claim the strict −1 dBTP policy. The suite must also show that the pinned analyzer catches a known inter-sample peak above sample peak, is monotone over controlled sweeps, and stays within the recorded contract for every policy cell. It must also prove that any internal resampling retains the complete qualified reconstruction band. B6 retains content to about 140 kHz and cannot be authorized by a 192 kHz analysis path; it requires a separately qualified full-band analyzer and a new policy/analyzer identity. A failed analyzer cell cannot substitute sample peak while retaining a dBTP label.
+
+## 3.5 Gain resolution
+
+For a singleton, the authority value is its measured true peak. For an independent album batch, it is the maximum measured true peak across all members. The resulting `G` is identical for every member.
+
+Terminal quantization, dither, and floating-point rounding add an **absolute linear-amplitude error**, not a signal-independent dB offset. A fixed dB guard would be mathematically invalid near silence. Each immutable target-rate/depth/toolchain cell therefore stores:
+
+```text
+ε = conservative upper bound on added true-peak amplitude, in full-scale linear units
+C = linear amplitude corresponding to the policy ceiling (-1.000000000 dBTP)
+S = floor_to_nano_db(20 log10(C - ε))
+```
+
+`ε` is serialized as a ceiling-rounded unsigned Q1.63 value (`max_added_peak_fs_q63_ceil`); `S` is the policy-generated `safe_pre_terminal_ceiling_dbtp`. Policy generation uses high-precision deterministic arithmetic, verifies `0 ≤ ε < C`, rounds `ε` upward and `S` downward, and records the derivation inputs/digest. Runtime gain authority performs no logarithm:
+
+```text
+maximum_ceiling_safe_gain = S - TP_upper
+```
+
+For TPDF integer realization, qualification derives `ε` from the quantizer and dither amplitude/support, then validates it empirically. For Shibata/noise-shaped realization, the policy requires an implementation-specific stability and worst-case peak-error bound, not merely a finite stress corpus. Float32/Float64 require a bound for gain evaluation, carrier read/write, and final format rounding. A cell without a defensible `ε`/`S` pair is unavailable. The post-final true-peak measurement remains the authoritative acceptance gate.
+
+Requested gains:
+
+```text
+Reference:   12.000000000 + 6.020599913 = 18.020599913 dB
+NativeLevel: 12.000000000 dB
+Fixed:       12.000000000 + fixed_gain_db
+```
+
+Resolution:
+
+```text
+Reference:   G = min(18.020599913, maximum_ceiling_safe_gain)
+NativeLevel: G = 12.000000000, or fail before finalization when unsafe
+Fixed:       G = 12.000000000 + fixed_gain_db, or fail before finalization when unsafe
+```
+
+Verified digital silence applies the requested gain only when the cell's terminal bound independently proves `ε < C`; this is always required for a supported cell. Reference is the only mode whose requested gain may be reduced automatically. No limiter, compressor, soft clipper, track-varying gain, or second gain adjustment is allowed. Changing analyzer uncertainty/error, `ε`, `S`, or their derivation requires a new policy ID.
+
+After finalization, the executor repeats the §3.4 measurement against `QPCM`. Reference, NativeLevel, and Fixed abort before packaging/publication unless the conservative bound is at or below −1.000000000 dBTP. There is no retry loop, gain backoff, or second dither realization after failure. NormalizePeak records the result but is explicitly outside that Reference ceiling contract. The log records reported/conservative pre-final and post-final peaks, analyzer bounds, `ε`, `S`, requested/applied gain, predicted upper bound, and the exact refusal reason.
+
+`NormalizePeak` remains a compatibility/user override. Its final command uses `norm <target_dbfs>` and is marked modified/unqualified; it never reuses “Auto.”
+

+## 3.7 Exact Cartesian command rule
+
+The exact argv for every supported `(source rate × target rate × depth)` cell is the Cartesian composition of:

+```text
+RIFF/WAV Int16/Int24/Float32/Float64:
+  ["-c:a", PCM_CODEC, "-f", "wav", FINAL]
+  (planner proves the predicted RIFF audio data plus every planned header, metadata, artwork, padding, and integrity chunk remains below the policy limit;
+   probe verifies the result is ordinary RIFF, not truncated or silently RF64)
+
+RF64 Int16/Int24/Float32/Float64:
+  ["-c:a", PCM_CODEC, "-f", "wav", "-rf64", "always", FINAL]

These output-byte-affecting values participate in behavior identity and receive decode-back qualification across their accepted ranges. No package argv contains `-af`, `-ar`, `-sample_fmt`, volume, filter, dither, normalization, or an additional audio stream. The policy pins the FFmpeg build, muxer/encoder identities, complete prefix/suffix, W64/RIFF/RF64 size and format rules, and the decoder used for verification.

The current planner already distinguishes direct SoX output from WAV-intermediate/final-encode paths and passes `apply_processing = false` to final encoding (`tonepoet-pipeline/src/plan.rs:1190-1242`); the new operation narrows that route to the exact argv above and makes the one-quantization proof format-independent. A candidate remains absent from the immutable policy until decoding the packaged result and comparing every channel/sample to `QPCM` succeeds for its exact depth/settings cells.
+
+Metadata, artwork, checksum tags, and ReplayGain tagging occur only after audio packaging through separately qualified non-audio mutations. The final verification is repeated after those mutations; any decoded-sample change aborts publication. ReplayGain may analyze/tag the final file but may not apply gain.

+# 4. Manual/Expert workflow schema and command assembly
+
+## 4.1 Scope
+
+Workflow schema version 1 is a strictly ordered linear pipeline. It supports the required FFmpeg→SoX→SSRC→FFmpeg chain without introducing a general DAG scheduler.
+
+Manual means exactly what the admitted snapshot says. Tonepoet adds no Reference DSP. It supplies planner-owned primary paths and backend safety flags only.
+
+A workflow is trusted local configuration, **not a sandbox**. Shell-free argv prevents shell expansion, but a media backend has its own nested languages and side-effecting options. Validation therefore has two explicit authority levels:
+
+- `Reject` accepts only fully classified option grammars. It hard-rejects response files, shell executables, stdin/stdout/pipe/device/network endpoints, undeclared additional inputs or outputs, user cwd/environment mutation, alternate primary outputs, undeclared auxiliary paths, known multipass/secondary outputs outside declared objects, and options that can undo tonepoet's safety prefix or endpoint ownership (`-stdin`, user overwrite-policy flags, backend-specific pipe/listen/protocol forms).
+- `TrustedUnsandboxed` permits otherwise unclassified literal argv after the same top-level shell/response-file and obvious endpoint checks, emits `MANUAL-UNCLASSIFIED-OPTION`, and records the policy and tokens in workflow/execution identity. It is an explicit acknowledgement that tonepoet cannot prove the semantics of an unknown FFmpeg filter expression, SoX effect, SSRC option, or future backend syntax. Such a workflow is treated like trusted local code and may perform backend-defined auxiliary I/O or side effects.
+
+Tonepoet guarantees planner-owned primary staging, post-run verification, cleanup of its own work root, and atomic publication of the declared primary chain. It does not claim side-effect confinement for `TrustedUnsandboxed`. A newly discovered or copied workflow is never auto-run: first selection presents normalized stages, dependencies, prefixed argv templates, identities, the authority level, and warnings for explicit acceptance.
+

For Ogg-family outputs, the codec and canonical extension disambiguate FLAC/Ogg (`flac+ogg+.ogg`) from native Opus (`opus+ogg+.opus`). Every earlier `{output}` binds to `PlanContext::intermediate_path(stage_index, output_extension)`; the current deterministic intermediate allocator is at `tonepoet-pipeline/src/plan.rs:70-93`.

+## 4.3 Canonicalization, admission, and object lifetime
+
+Loading a workflow performs:
+
+1. Stable-read the workflow definition itself: reject symlinks/non-regular files, capture pre-read identity/metadata, read UTF-8 bytes, and reject post-read identity/metadata change.
+2. Parse TOML with duplicate/unknown-field rejection and schema-version dispatch.
+3. Normalize enum spelling/defaults while preserving each argv token byte-for-byte as UTF-8; no whitespace splitting. Workflow names are stored and looked up as exact, case-sensitive Unicode scalar sequences with no Unicode normalization; names/IDs reject NUL and Unicode control characters, and every argv token rejects NUL.
+4. Resolve relative dependency paths against the workflow file's directory; absolute paths are accepted as provenance only. Dependency IDs use the same ASCII grammar as stage IDs.
+5. Stable-read each dependency, reject symlinks, stream it into a temporary content-addressed object while hashing, verify post-read identity/metadata, `fsync`, atomically publish by SHA-256 key, and `fsync` the object directory. Existing matching objects are reused; collision/mismatch fails closed.
+6. Canonically serialize `schema_version`, `continuous_source_handling`, `unclassified_option_policy`, dependency IDs/sizes/content hashes/object keys, stage IDs/backends/argv, and output contracts in fixed field order with LF endings. Exclude display name, description, definition path, and dependency source paths.
+7. Hash those bytes and store the normalized snapshot plus object references.
+
+Persistent objects live under `<state-root>/tonepoet/workflow-objects/sha256/<prefix>/<digest>`. They are never passed directly to a child. Run preparation rehashes each object, copies or copy-on-write clones it—never hard-links it—into a per-run dependency directory, verifies the materialization, and binds that path. Each consuming stage is followed by content revalidation. A backend can invalidate its run copy but cannot corrupt the shared object.
+
+Garbage collection is mark-and-sweep under the state-store lock, not best-effort reference counting. Roots are persisted queue snapshots and active run/workflow-admission leases acquired before an item can reference an object. Startup/recovery discards provably stale leases and rescans the queue before sweep. Manifests containing dependency hashes are provenance/rerun evidence, not execution roots, unless a future feature explicitly supports recreating work from them. A queued item therefore survives source workflow/dependency deletion, while unreferenced objects are eventually reclaimable.
+
+## 4.4 Placeholder and argv rules
+
+Each stage must contain exactly one token equal to `{input}` and exactly one token equal to `{output}`. It may additionally contain whole-token `{dependency:ID}` references declared in the top-level dependency list. Placeholders are whole tokens; interpolation inside a token is rejected. This makes path binding unambiguous and prevents a user string from becoming two argv elements.
+
+Expansion rules:
+
+```text
+{input}  → verified planner-owned source materialization for stage 0; previous stage output for later stages
+{output}        → planner-owned stage output path
+{dependency:ID} → revalidated, planner-owned per-run materialization of the recorded content object
+```
+
+No other placeholders exist in schema v1. There is no shell, environment expansion, command substitution, globbing, pipe, redirection, response-file expansion, or conditional expression. Backend-aware parsing classifies option arity and path-bearing arguments before admission. Unclassified options require `TrustedUnsandboxed`; the loader still rejects shell executables, response files, NUL, and obvious top-level endpoint/ownership overrides, but it does not pretend to understand or confine nested backend languages.
+
+Backend executable names are not stored in the file. `backend = "sox"` maps to the built-in `ToolIdentifier::Sox`, and similarly for FFmpeg and SSRC. This works with the current orchestrator's built-in-only adapter rather than weakening its rejection of arbitrary planner tools (`src/convert/pipeline/planned_adapter.rs:35-46`).
+
+Tonepoet uses the planner adapter's deterministic `LC_ALL=C` environment (`src/convert/pipeline/planned_adapter.rs:54-75`) and prepends only backend safety tokens that do not change audio semantics:
+
+```text
+FFmpeg: always prepend -nostdin -hide_banner -y
+SoX:    always prepend -S; no implicit DSP token
+SSRC:   prepend no token
+```
+
+`-y` is safe because `{output}` is always a fresh/stale-cleaned planner-owned staging path. The loader rejects user-supplied FFmpeg `-stdin`, `-y`, `-n`, protocol/pipe/listen endpoints, and any other option that can reverse the fixed safety/ownership prefix or create an undeclared endpoint.
+
+Stage 0 never receives the original source pathname. It binds `{input}` to the common native-v2 `PreparedSourceMaterialization` from §2.2. Later stages receive only prior planner-owned outputs. A backend can corrupt its run-local input, but post-stage identity/hash checks fail the run without damaging the user's source or an earlier persistent object.
+
+Read-only auxiliary files such as FIR coefficient files must be declared as dependencies and referenced with `{dependency:ID}`. Admission snapshots each file into the content-addressed object store described in §4.3. Run preparation verifies the recorded object and creates a non-hard-linked per-run materialization under the deterministic work root; only that materialization is passed to the backend. The executor verifies it before and after every consuming stage. A missing/tampered persistent object or changed per-run materialization fails closed, but a backend cannot corrupt the shared persistent object merely by writing the path it received. Changes to the original source path do not affect admitted work. Workflow stages cannot declare their own cwd or output path.
+
+## 4.5 Stage output verification
+
+After each successful stage, tonepoet probes the produced file before launching the next stage. `Raw` output is a special case: it requires explicit sample rate, sample format, and channel count; byte length must be divisible by the declared frame size and yields the exact frame count. Raw cannot be the final output while `AudioFormat` has no corresponding requested target.
+
+Hard failures:
+
+- output missing, empty, or outside the allocated path;
+- probe cannot identify the declared container and codec;
+- a declared sample rate, format, or channel count does not match;
+- the observed input/output sample-format transition contradicts the declared quantization action (for example, float-to-integer with `quantization = "none"` or `preserve`);
+- final `resolved_target` does not equal the requested target, or its container+codec+extension triple does not match that target;
+- pre/post identity, size, and content-hash verification proves that the stage changed its input file, a dependency materialization, or another stage's output.
+
+`quantization` declares what the stage does, not merely the representation it emits: `final_integer` owns the one word-length reduction, while `preserve` promises that an encoder/container stage retains the incoming sample values. `dither` declares a stage-owned operation. Ordinary probes cannot prove dither, so these declarations are lint/provenance inputs and must be backed by transcript and decode-back tests rather than treated as self-authenticating proof.
+
+## 4.6 Linter
+
+The linter is conservative and never rewrites argv. Findings have stable codes and severities.
+
+Warnings include:
+
+```text
+DSD-MANUAL-001  no recognizable antialiasing decimator before a lower PCM rate
+DSD-MANUAL-002  more than one recognizable rate conversion
+DSD-MANUAL-003  integer output before a later sample-altering stage
+DSD-MANUAL-004  more than one declared dither/noise-shaping stage
+DSD-MANUAL-005  positive-gain/FIR chain with no recognizable prior headroom
+DSD-MANUAL-006  FFmpeg DSD/DST decode followed by wording that claims native-SoX Reference
+DSD-MANUAL-007  unqualified backend version
+DSD-MANUAL-008  final lossy encode after a declared integer quantization stage
+DSD-MANUAL-009  per-track execution acknowledged for a continuous programme
+MANUAL-UNCLASSIFIED-OPTION  explicitly accepted backend option lacks a classifier
+```
+
+Recognition is intentionally narrow and token-based. Failure to recognize an expert expression produces “unknown,” not a false assertion. No warning changes the plan.
+
+## 4.7 Worked FFmpeg→SoX→SSRC→FFmpeg example
+
+This example is illustrative expert intent, not a Reference recommendation. The SSRC dither ID is deliberately a user-resolved value because supported IDs must be discovered from the installed binary.
+
+```toml
+schema_version = 1
+name = "ffmpeg-sox-ssrc-flac"
+description = "Stereo: explicit FFmpeg decode, SoX FIR/effects, SSRC rate conversion and 16-bit shaping, FFmpeg FLAC encode"
+continuous_source_handling = "reject"
+unclassified_option_policy = "reject" # reject | trusted_unsandboxed
+
+[[stage]]
+id = "decode"
+backend = "ffmpeg"
+args = [
+  "-i", "{input}",
+  "-map", "0:a:0",
+  "-vn", "-sn", "-dn",
+  "-c:a", "pcm_f32le",
+  "-f", "wav",
+  "{output}"
+]
+output_extension = "wav"
+[stage.output]
+container = "riff_wav"
+codec = "pcm"
+sample_format = "f32"
+channels = 2
+quantization = "none"
+dither = "none"
+
+[[stage]]
+id = "fir"
+backend = "sox"
+args = [
+  "{input}",
+  "-t", "wav", "-e", "floating-point", "-b", "32", "{output}",
+  "gain", "-12.0",
+  "sinc", "-a", "180", "-L", "-t", "15000", "-30000"
+]
+output_extension = "wav"
+[stage.output]
+container = "riff_wav"
+codec = "pcm"
+sample_format = "f32"
+channels = 2
+quantization = "none"
+dither = "none"
+
+[[stage]]
+id = "resample_quantize"
+backend = "ssrc"
+args = [
+  "--rate", "192000",
+  "--profile", "high",
+  "--bits", "16",
+  "--dither", "2",
+  "--pdf", "1",
+  "{input}", "{output}"
+]
+output_extension = "wav"
+[stage.output]
+container = "riff_wav"
+codec = "pcm"
+sample_rate_hz = 192000
+sample_format = "s16"
+channels = 2
+quantization = "final_integer"
+dither = "noise_shaped"
+
+[[stage]]
+id = "encode"
+backend = "ffmpeg"
+args = [
+  "-i", "{input}",
+  "-map", "0:a:0",
+  "-c:a", "flac",
+  "-sample_fmt", "s16",
+  "{output}"
+]
+output_extension = "flac"
+[stage.output]
+resolved_target = "flac_native"
+container = "flac"
+codec = "flac"
+sample_rate_hz = 192000
+sample_format = "s16"
+channels = 2
+quantization = "preserve"
+dither = "none"
+```
+
+This example assumes that the installed SSRC reports shaped-dither ID 2 as valid at 192 kHz; workflow admission must discover and verify that fact rather than trusting the example. The resulting argv is exactly each backend's safety prefix followed by the listed tokens with whole-token placeholder substitution. Tonepoet does not add `rate -u`, libsoxr, gain restoration, DSD compensation, or another dither. The final verification decodes the FLAC and compares samples with the stage-3 WAV.
+
+The existing built-in SSRC command shape already treats `--dither`, `--pdf`, and `--bits` as one terminal operation and validates rate-dependent dither IDs (`tonepoet-pipeline/src/plugins.rs:336-421`). The workflow system does not reuse its automatic mapping; it executes the user's explicit tokens and warns when the installed binary does not advertise the requested ID.

+## 4.8 Workflow storage and discovery
+
+Use the application configuration root already used for configuration and presets (`src/config.rs:1985-1996`, `src/tui/presets.rs:476-490`) with a new `workflows/` directory:
+
+```text
+<config-root>/tonepoet/workflows/*.toml
+```
+
+Discovery is deterministic:
+
+- regular files only;
+- `.toml` extension only;
+- exact, case-sensitive names with no Unicode normalization;
+- sorted by the UTF-8 bytes of the exact name, then the canonical path bytes;
+- duplicate exact names are an error shown in the selector;
+- unreadable/invalid files are listed as disabled with the parse error;
+- no recursive directory walk in schema v1.

+The CLI also accepts an explicit workflow file through a distinct path-valued option. Named lookup and path lookup are never inferred from string shape; both resolve to the same snapshot before queue admission.

+# 5. Exposure design
+
+## 5.1 TUI format pane
+
+Add these `FormatField` rows when source is DSD and target is PCM:
+
+```text
+DSD path      [reference | manual]
+DSD profile   [reference | wideband]
+DSD gain      [reference | native | fixed | normalize]
+DSD gain dB   [numeric; fixed only]
+normalize dBFS [numeric; normalize only]
+workflow      [named workflow; manual only]
+```
+
+The current format-pane navigation is an explicit `FormatField` enum and visible-row sequence (`src/tui/app.rs:2938-2993`). The new fields join that sequence and the existing keyboard/mouse mapping rather than creating a separate modal navigation model.
+
+Interaction rules:
+
+- Selecting **Reference** enables profile and gain rows, disables workflow, and re-derives dither/resampler display.
+- Selecting **Manual** disables profile/gain controls, enables workflow, and leaves all DSP ownership to the selected snapshot.
+- `Wideband` is disabled for DSD64, disabled where target Nyquist cannot contain it, and visibly marked provisional for B6.
+- `Fixed` enables only the fixed-gain dB row. `Normalize` enables only the normalize-target dBFS row. Other gain modes disable both; hidden stale values remain serialized for audit but are inactive and excluded from behavior identity.
+- Under the Reference reconstruction profile, `Native`, `Fixed`, and `Normalize` display “Reference reconstruction; modified gain policy.” Under `Wideband`, the status instead names the provisional wideband reconstruction and never uses the full Reference label. Normalize additionally displays “legacy peak normalization; measured but not governed by the Reference −1 dBTP acceptance ceiling.”
+- An unsupported source/target cell remains selectable only if the UI can immediately show the planner-grade reason; conversion commit is disabled until corrected.
+
+The TUI state stores the selection and resolved workflow identity, then `convert_actions` constructs the full new settings instead of defaulting the whole DSD struct and changing only gain. The current limited construction occurs at `src/tui/convert_actions.rs:371-400`.
+
+## 5.2 Dither pill interaction
+
+Reference owns terminal quantization:
+
+| Resolved depth | Dither row in Reference |
+|---|---|
+| Int16 | locked: `Shibata (Reference)` |
+| Int24 | locked: `TPDF (Reference)` |
+| Float32/Float64 | locked: `none (float)` |
+| Int8/Int32 | disabled/unsupported |
+
+A locked value is shown only when the entire source/rate/depth/container cell exists in the selected immutable policy. Candidate or rejected cells show the row disabled with the planner-grade reason; the dither label alone never implies qualification. The user's generic dither selection is not overwritten in state; it is ignored by the Reference plan and restored when leaving Reference. This avoids destructive UI cascades while guaranteeing that generic `PipelineSettings.dither_type` cannot alter Reference argv.
+
+Manual mode labels the generic dither row `workflow-owned` and disables it. The workflow file must contain any dither tokens.
+
+The current SoX DSD builder appends generic dither based on `PipelineSettings.dither_type` (`tonepoet-pipeline/src/plugins.rs:1680-1687`). The new operations never call that helper.
+
+## 5.3 Resampler pill and sinc firewall
+
+Reference displays a locked resampler value:
+
+```text
+SoX-ng Reference (rate -u)
+```
+
+The generic resampler pill, resample quality, Nyquist transition, SSRC advanced options, SoXR options, and `sox_resampler.sinc_*` do not participate in Reference command assembly. They remain in TUI state for PCM conversions and reappear unchanged when the conversion direction changes.
+
+Manual mode displays `workflow-owned` and similarly disables generic resampler controls.
+
+This is a hard planner firewall, not only a UI convention. Reference fingerprints and argv ignore generic resampler fields, and validation rejects any attempt to project them into a Reference operation. The current generic SoX sinc overrides are separate `SoxResamplerSettings` fields (`tonepoet-pipeline/src/settings.rs:648-690`) and are currently populated from the advanced TUI (`src/tui/convert_actions.rs:446-456`); they remain PCM→PCM only.
+
+## 5.4 CLI
+
+Add to `tonepoet convert`:
+
+```text
+--dsd-path <reference|manual>
+--dsd-profile <reference|wideband>
+--dsd-gain <reference|native|fixed|normalize>
+--dsd-gain-db <DB>
+--dsd-normalize-target-dbfs <DBFS>
+--dsd-workflow <NAME>
+--dsd-workflow-file <PATH>
+```
+
+Rules:
+
+- Defaults are Reference/Reference/Reference.
+- `--dsd-gain-db` requires `--dsd-gain fixed`; `--dsd-normalize-target-dbfs` requires `--dsd-gain normalize`; both use the exact fixed-point decimal grammar.
+- `--dsd-workflow` and `--dsd-workflow-file` are mutually exclusive; Manual requires exactly one of them.
+- `--dsd-profile`, `--dsd-gain`, and gain numeric flags conflict with Manual; workflow flags conflict with Reference.
+- Every DSD-path/profile/gain/workflow flag is an error when the resolved conversion direction is not DSD→PCM; no flag is silently ignored.
+- `--dsd-workflow` performs exact named lookup in the workflow directory; `--dsd-workflow-file` is the only explicit-path form.
+- CLI help says Reference is lossless-only and lists the fail-closed source/rate limits.
+
+The CLI constructs a full `PipelineSettings`, resolves the existing format+container selection into the exact `ResolvedOutputTarget`, and attaches it to `ConversionOptions.pipeline_settings`/`ConversionItem.pipeline_settings`. It does not extend the legacy projection. The full-settings handoff is already the declared production route (`src/convert/pipeline/unified_request.rs:27-54`, `src/convert/pipeline/unified_request.rs:64-81`).

+`tests/settings_sentinel.rs` records every new DSD/workflow field as `LegacyProjectionStatus::Unrepresentable`. That is intentional and honest; new CLI/TUI callers are required to attach full settings.

+## 5.6 Presets
+
+Increment the persisted TUI preset schema from 3 to 4. The exact v4 wire additions are:
+
+```rust
+pub struct PresetWireV4 {
+    pub version: u32, // exactly 4
+    // existing v3 fields
+    pub output_target: String, // required canonical ResolvedOutputTarget key
+    pub dsd_path: Option<String>,
+    pub dsd_profile: Option<String>,
+    pub dsd_gain: Option<String>,
+    pub dsd_gain_db: Option<String>, // canonical signed decimal, parsed to DbNano
+    pub dsd_normalize_target_dbfs: Option<String>, // canonical signed decimal, parsed to DbNano
+    pub dsd_workflow_name: Option<String>,
+    pub dsd_workflow_sha256: Option<String>,
+}
+
+pub enum NormalizedPresetOutputTarget {
+    Resolved(ResolvedOutputTarget),
+    LegacyUnspecified, // produced only while converting exact v2/v3 wires
+}
+```
+
+The optional DSD fields use explicit `None` when inapplicable; `output_target` is never optional in a v4 file. Version-specific wire conversion, not `#[serde(default)]` on a single catch-all struct, supplies the internal legacy sentinel.
+
+New presets always write the exact snake-case `ResolvedOutputTarget` key alongside `format`; DSD enum fields likewise use persisted keys such as `native_level` and `normalize_peak`, not shorter UI/CLI labels; the two must agree or the field is refused. Canonical examples are `flac_native`, `wav_riff`, `wav_rf64`, `wav_w64`, `alac_m4a`, and `opus_native`; every enum variant has one frozen lowercase key. They also write all applicable DSD fields. The current preset schema omits the selected container even though `FormatState` stores `selected_container_index` (`src/tui/app.rs:3235`, `src/tui/app.rs:3474`, `src/tui/app.rs:3522-3527`); v4 closes that behavior-identity gap rather than preserving it for new Reference work. The workflow name is for selection and display; the digest detects that the named file has changed. Applying a preset with a changed digest requires an explicit “use updated workflow” confirmation before conversion, after which the new snapshot is stored on the queue item.
+
+Preset loading becomes version-dispatched rather than “try one struct, then reinterpret as another.” Parse the top-level TOML map with duplicate-key rejection, inspect `version`, and dispatch to exact `PresetWireV2`, `PresetWireV3`, or `PresetWireV4` schemas with unknown-field rejection. An unsupported version fails explicitly. The older wizard schema is attempted only when the document has no TUI `version` discriminator and matches the frozen wizard key set; a malformed/future TUI preset is never reinterpreted as a wizard preset. This replaces the current parse-then-fallback behavior (`src/tui/presets.rs:576-595`). V4 saves use a same-directory temporary file, flush/`fsync`, atomic replace, and parent-directory sync rather than the current direct `fs::write` (`src/tui/presets.rs:599-612`).
+
+Old v2/v3 presets have no DSD→PCM controls (`src/tui/presets.rs:29-75`, `src/tui/presets.rs:104-149`) and therefore load the new Reference path/profile/gain defaults. They also have no container field. Existing preset application selects the format and reapplies format constraints but never resets or applies `selected_container_index` (`src/tui/presets.rs:162-184`, `src/tui/app.rs:4181-4340`); only an interactive format change resets that index to zero (`src/tui/app.rs:3898-3904`). A converted v2/v3 `LegacyUnspecified` target must therefore **not** be guessed or silently inherited for native DSD admission; an actually missing v4 `output_target` is a parse error. The UI preserves the visible historical selection, marks the preset `PRESET-CONTAINER-UNSPECIFIED`, and requires the user to confirm a container before Reference/Manual work can be queued; saving the preset as v4 records the exact key. This does not alter persisted queued work because presets are UI configurations, not already-admitted execution plans. The existing loader already uses serde defaults and reports refused fields rather than pretending every value applied (`src/tui/presets.rs:77-101`, `src/tui/presets.rs:152-167`).

+# 6. Test and qualification plan

+## 6.1 Test taxonomy
+
+- **Automated test:** pure Rust/unit/integration test using planner structures, parsers, fixtures, or `StubToolRunner`; no external tool required.

+- **Out of scope:** unsupported cells with a planner rejection test.

+# 8. Compatibility and migration
+
+## 8.1 Existing queued work
+
+Persisted queue items may already contain complete `PipelineSettings`; queue persistence stores that field as optional (`src/convert/queue.rs:198-203`), while the scheduler invokes the full-settings validator before collecting runnable items (`src/convert/queue.rs:911-939`, `src/convert/processor.rs:1772-1777`). Complete old settings deserialize through the legacy-flat compatibility mapping and retain old output semantics under the private `LegacyFlatV1` origin. The old gain semantics being preserved are the current `norm`/fixed/disabled branches (`tonepoet-pipeline/src/plugins.rs:1712-1738`).
+
+A persisted queued row that lacks full settings/request is **not** repaired by calling a new default. Resume leaves it blocked and reports `QUEUE-SETTINGS-MIGRATION-REQUIRED`. An explicit migration/reconfiguration action may reconstruct only values that the legacy row actually represents, shows every output-affecting gap, and requires acceptance before admission. For legacy DSD→PCM rows, any accepted reconstruction uses the frozen old defaults—Auto lowpass, Disabled gain, 0.15 dB old normalization margin, no fixed gain, and the old sinc defaults—not the new Reference defaults (`tonepoet-pipeline/src/settings.rs:752-766`). If the row lacks enough persisted intent to reproduce those semantics, migration refuses it rather than guessing.
+
+Consequences:
+
+- An already queued old `Auto` continues to run SoX peak normalization, not fixed DSD compensation.
+- An old Disabled item remains uncompensated/native-level, not new Reference gain.
+- An old manual dB continues as fixed gain.
+- An old explicit Sinc setting executes through the private legacy compatibility operation with its original pre-rate custom-sinc argv. Opening it for editing labels it `legacy custom sinc`; changing it requires an explicit Manual workflow, and reconfiguration clears the compatibility snapshot.
+- Reopening and explicitly reconfiguring the item in the new UI writes native v2 settings and a new fingerprint.
+
+The old compatibility chain remains private, receives regression transcript tests, and is not offered for new conversions. It may be removed only in a future persistence-version migration with an explicit queue upgrade tool.
+
+## 8.2 New defaults
+
+New conversions use Reference/Reference/Reference. This is a deliberate behavior change and therefore changes fingerprints and output. It is not applied retroactively to admitted queued work.
+
+Old TUI presets do not contain an execution plan or old DSD gain fields, so they load the new Reference path/profile/gain defaults. Because they also omit container identity, native DSD admission remains blocked with `PRESET-CONTAINER-UNSPECIFIED` until the user confirms the visible target; the preset can then be resaved as v4 with its exact `output_target` key. A one-time UI notice explains both changes.
+
+## 8.3 Current gain modes
+
+User-facing mapping:
+
+```text
+old Disabled → Native
+old Auto     → Normalize (legacy peak)
+old Manual   → Fixed
+new Auto concept → Reference
+```
+
+The UI and docs stop using “Auto” as an enum label because it previously meant normalization and would be ambiguous. “Reference” is the qualified default; “Normalize” states the actual operation.
+
+## 8.4 Fingerprint and manifest changes
+
+All newly configured DSD→PCM conversions receive a new native-v2 settings-snapshot domain and a new source-aware behavior-fingerprint domain because:
+
+- pathway is explicit;
+- policy version is explicit;
+- profile is a full passband/transition policy rather than one cutoff;
+- gain semantics changed;
+- headroom/measurement/deferred finalization are part of the policy and plan;
+- workflow content is hashed when Manual;
+- the exact typed codec+container output target replaces ambiguous extension/raw-flag identity for native DSD routes.
+
+Legacy queue fingerprints remain under the unchanged v1 algorithm/domain. The native-v2 snapshot hash changes only for fields its canonical schema declares fingerprint-bearing; the Reference/Manual behavior hash remains narrower and source-aware. There is no attempt to make old and new settings collide merely because a particular fixture happens to produce similar samples.
+
+Bump `MANIFEST_VERSION` from its current value of 1 (`src/convert/pipeline/manifest.rs:12-22`) to 2 and add the exact route-level and per-track identities in §1.7. Reference-v2 and Manual-v2 manifests carry the native settings snapshot at route level and behavior/execution/semantic-plan identity per track; Reference may additionally carry exact programme identity. Legacy-route v2 envelopes carry only the unchanged v1 authority plus existing source/output facts. The v1 reader remains available for conservative compatibility; v1 data is never upgraded in place and never receives synthesized behavior or execution identity. A successful new-path whole-album conversion commits its mandatory manifest inside the directory rename; an incremental conversion uses the serialized journal/recovery protocol in §2.7, not an assumed atomic pair of independent files.
+
+## 8.5 TUI state and presets
+
+`FormatState` gains pathway/profile/workflow and new gain choices. It is constructed from program defaults rather than deserialized session state (`src/tui/app.rs:3168-3282`); there is therefore no durable in-memory-state migration beyond preset loading.
+
+Preset v4 writes stable canonical keys, not labels. The loader version-dispatches exact v2/v3/v4 wire structs before conversion to `TuiPreset`; unsupported or malformed TUI versions never fall through to the wizard schema. Applying a preset is all-or-refused per field, consistent with the current `PresetApplyReport` model (`src/tui/presets.rs:77-101`). A format/`output_target` mismatch, an omitted target inherited from v2/v3 for native DSD, or a missing workflow is reported as a refused/unresolved field and conversion remains disabled until explicitly resolved.
+
+## 8.6 CLI and legacy bridge
+
+New CLI flags always attach full settings. The compatibility projection is already documented as outside the production request path (`src/convert/pipeline/unified_request.rs:221-236`), but its implementation currently starts from `PipelineSettings::default()` (`src/convert/pipeline/unified_request.rs:244-250`, `src/convert/pipeline/unified_request.rs:293-296`) and later assigns `DsdSettings::default()` (`src/convert/pipeline/unified_request.rs:499-531`). After native defaults change, that is no longer an acceptable legacy authority. The implementation round must introduce a frozen `LegacyPipelineSettingsV1`/explicit constructor containing every historical default and use it only in migration/compatibility tooling; it must never derive legacy semantics from the evolving native `Default` implementation. Production `build_pipeline_request()` continues to require full settings or a prebuilt request, and the sentinel prevents any future claim that new DSD fields are representable through `ConversionOptions`.
+
+## 8.7 Dead surfaces and docs
+
+The implementation removes public references to the old DSD→PCM lowpass selector, old source-rate cutoff table, and dual-use DSD sinc. Documentation points users to Reference profiles or Manual workflows. PCM→DSD sinc remains available under its renamed, direction-specific type.

+# 9. Open questions and recommendations
+
+These are the only product decisions not safely inferable from the supplied evidence.
+
+## Q1. What exact target-limited profile should DSD128/DSD256 → 88.2 kHz use?
+
+**Evidence gap:** v9 names a target-limited profile but gives no passband/transition pair. Inventing a clipped or proportional B4/B5 response would be an unmeasured product policy.
+
+**Recommendation:** keep those two cells rejected by `SoxNg14801V1`. Commission and qualify an explicit target-88 profile, then mint a new append-only policy ID. Do not revise a table under the old ID.
+
+## Q2. Should DSD128/DSD256 → 96 kHz ship before direct qualification?
+
+**Evidence gap:** v9 says intended B4 and explicitly conditions it on direct 96 kHz qualification.
+
+**Recommendation:** no. Keep both cells rejected by v1. After response, alias, boundary, duration, headroom, analyzer, and terminal-realization qualification passes, mint a new policy ID; the settings schema can remain unchanged.
+
+## Q3. Should B6 be visible before its provisional qualification passes?
+
+**Recommendation:** show it in help/UI as `Wideband (B6; unavailable—qualification pending)` so the product model is discoverable, but do not allow queue admission. Enabling it requires both the reconstruction qualification and a full-band peak analyzer that covers the 140 kHz retained band; the initial 192 kHz `loudnorm` route is not sufficient. After both gates pass under a new policy/analyzer identity, enable it only for DSD256 targets at 352.8 kHz and above, with the ultrasonic-noise disclosure.
+
+## Q4. Should Reference feed lossy encoders?
+
+**Evidence gap:** the qualified chain terminates in final PCM quantization and lossless encoding. A lossy encoder introduces another sample-altering stage and owns its own internal precision/quantization.
+
+**Recommendation:** Reference v1 rejects lossy targets. Users may choose Manual and explicitly encode MP3/AAC/Opus. A future “Reference reconstruction front-end” product mode can be designed and qualified separately without claiming the full lossless Reference pathway.
+
+## Q5. Should Int32 integer output be accepted without dither?
+
+**Evidence gap:** v9 defines 16-bit, 24-bit, and floating-point terminal policy, not 32-bit integer.
+
+**Recommendation:** reject Int32 in policy v1. Add it only after a sample-format/packaging qualification and document whether the terminal conversion uses no dither or TPDF. Float32 is the evidence-defined no-dither high-precision alternative only in a policy whose Float32 carrier/gain/peak cell has passed qualification.
+
+## Q6. May Manual workflows opt into per-track processing of a continuous image?
+
+**Recommendation:** yes, but only through schema-v1 `continuous_source_handling = "split_then_process_acknowledged"`; the default is `reject`. The UI must disclose that decoding/FIR/resampler/noise-shaper state can reset at every boundary. Reference never permits the override, and schema v1 does not silently reinterpret this as process-before-split.
+
+## Q7. Should programme Reference overwrite or merge into an existing album directory?
+
+**Recommendation:** no for policy v1. Enable programme-wide Reference only when the complete album can be published by one sibling-directory rename into a previously absent destination. Existing-directory merge/overwrite should remain unavailable until a journaled swap/recovery design proves that crashes cannot expose a mixed old/new member set. The new singleton Reference and Manual pathways use the file transaction in §2.7; existing unrelated conversion routes retain their current publication behavior unless that capability is deliberately adopted and regression-qualified. A file transaction does not upgrade album-directory replacement into an all-members transaction.
+
+## Q8. For independently stored tracks, is the gain programme an album release or one disc?
+
+**Product effect:** the choice can change the maximum measured peak, applied gain, and every output byte in a multi-disc release. The current conversion-log batch transport is folder-oriented and cannot answer this by itself (`src/convert/processor.rs:331-357`).
+
+**Recommendation:** freeze `ResolvedAlbumRelease` as the first programme policy: all selected discs that resolve unambiguously to one release share one gain, preserving cross-disc level relationships. If release identity or membership is ambiguous, reject multi-member Reference and require the user to correct grouping or convert as explicit singletons; never fall back silently to per-disc/per-track gain. A future per-disc option must be an explicit policy/setting value included in fingerprints and programme identity.
+
