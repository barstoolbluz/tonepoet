## Failure, partial output, and cancellation contract

- **Optional source observation fails before application, conversion succeeds:** preserve the successful staged outputs, discard all or none of the source observations, log a causally attributed reason, and use the existing native **post-output** ReplayGain path for the actual successful cohort. Do not silently suppress requested ReplayGain and do not restart successful conversion workers. A source-generation mismatch invalidates source observation; it must never be used to tag outputs. Do not invent retries to hide an unstable input.
- **Conversion fails or an album is partial:** retain existing `FailurePolicy`, original causal failure and per-track records. Do not apply the full original album scan to a smaller successful set. Under any allowed partial-publication path, existing output measurement owns the actual successful cohort; discard stale source statistics. No second publication or artifact naming change.
- **A retained measurement reaches metadata application and its writer/binding fails:** follow the existing *fatal* metadata-stage error, not a rescanning fallback that could obscure the writer failure.
- **User cancellation / timeout / early EOF / corrupt CRC / observer panic / disk-full or FIFO error:** terminate all related meter processes, settle/reap children, release each permit exactly once, avoid waiting forever on an unopened or orphaned pipe, clean private scratch and preserve the correct album failure. No output destination control files, unrequested sidecars, stray FIFO, or log fiction. One measurement recovery must not be miscounted as a second S3 album attempt.
- S1, the default-off branch, unsupported platforms, inherited-tag disqualification and all out-of-band plans must remain behaviourally unchanged. Keep the old post-output meter as an independently testable fallback/rollback mechanism.
