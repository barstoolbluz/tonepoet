# ADR-CUE-PAR-001 — narrowly qualified ranged FLAC workers

**2026-10-22; status PROPOSED / NOT BUILD-QUALIFIED.** Authority: actual baseline source paths in [01_SOURCE_AUDIT.md](01_SOURCE_AUDIT.md). This is a reversible decision, not a blanket assertion that range decoding is exact or faster.

## Decision

Adopt a **minimal capability-selected S4 hybrid**: preserve the existing S1 one-decoder/sequential-encoder transport and all current staged-carrier routes; add an **opt-in S3 independent-decoder-range → existing-plan-encoder path** for **one exact-sample FLAC physical image with ordinary, unchanged sample-rate/depth FLAC track outputs**. Enable only after exact boundary, resource, metadata, ReplayGain, fault and elapsed-time gates. No special generic codec infrastructure and no duplicate metadata, conversion planner, gain engine, DSP implementation or publisher.

**First shippable milestone:** an explicitly gated, correctly recorded and safely published parallel FLAC image → FLAC tracks conversion preserving **ReplayGain Both** behavior and all other existing defaults; the user can always use legacy S1. A later packet promotes auto-admission only for workloads/hardware where repeatable measured net gain exists. First milestone is *not* "every supported output format is parallel".

## Four strategies — actual tradeoffs

| Choice | What it executes | Practical benefits | Technical limitations and selection |
|---|---|---|---|
| S1: existing shared sequential stream | FFmpeg decode once from start; discard unselected bytes; bounded 64-KiB pipe; encode tracks one by one (`stages.rs:44190-44224`, `tool.rs:2374-2700`) | Strong established boundaries, no repeated decode/startup, low memory, compatible Unix source-pass ReplayGain | Serial encode CPU in one group; favored for short tracks, HDD, low CPU, narrow container operation |
| S2: one decoder, concurrent encoders | Single sequential PCM stream feeding concurrent encoder input pipes | Source traversal once, encoder process overlap near boundaries | Later tracks cannot receive bytes until decoder reaches them; overlapping long tracks requires buffering PCM (minutes × channels × bytes), staging, or encoder startup just-in-time; little speedup from naive bounded queues; back-pressure can serialize it anyway. **Not selected** without evidence |
| S3: independent range worker per track | Seek/read FLAC near sample start, establish exact PCM range, pipe to planner-authorized encoder; bounded N simultaneous tracks | Independent encoder CPU and concurrent decode; bounded streaming memory without entire-track WAVs; can accelerate single-image albums | Requires **proof** sample-exact seeks despite granularity/priming/rounding; extra decode seek cost and read contention; multiple FFmpeg/SoX processes; resource fairness; RG source-pass FIFO can't simply carry over. **Pilot** |
| S4: tiny hybrid | S1 or S3 selected by source capability, plan, effects, workload and shared budget | Performance where qualified with safe fallback on others | Must remain small: one FLAC range capability first; no speculative multi-format registry |

### Why worker per track, not another custom thread pool

Track outputs and metadata are already isolated as `ScheduledCueStreamTrack` / `ScheduledTrackOutput` (`src/convert/pipeline/stages.rs:43897-45585`), and the processor already has a global queue (`src/convert/processor.rs:5350-5555`). A worker's useful unit is **one independently addressable PCM interval plus one authorized plan**, not a second conversion subsystem. Launch native processes through existing `ToolRunner`/version cache/cancellation, return one staged artifact and record indexed by immutable authored ordinal; retain the existing album barrier, ReplayGain and publisher. New concurrency lives inside this one scheduled CUE work unit in its initial pilot, so album lifecycle/partial failure ownership is not multiplied.

The processor already shares `ToolConcurrencyLimits` across albums and unrelated work (`src/convert/processor.rs:2167-2185`; `src/convert/pipeline/track_executor.rs:709-804`). **Extend that limiter only at the new S3 two-child launch boundary**, counting both live children (two FFmpeg permits for an FFmpeg decoder + FFmpeg encoder), and avoid a second permit acquisition by calling the existing unwrapped `ToolRunner::run_pipeline`. The current reference/segmented helper collapses family duplicates (`track_executor.rs:11607-11661`); S3 cannot use that one-per-family accounting. Keep unrelated execution behavior unchanged unless a focused S3 coexistence test proves a specific undercount needs a narrow correction. Derive bounded live RAM/FD/I/O upper limits from admitted S3 workers × known bounded pipe/process costs; a new global weighted resource-management framework is not a prerequisite.

## Admission contract and fallback

In order, before launching any competing decoder:

1. Provenance: existing queue/materializer produced genuine `CueStreamSegment` from **one physical** `.flac` with PCM coding, channels, exact sample count and agreed sample rate (`materializer_cue.rs:491-690`); canonical resolved path remains authority, not extension-only magic.
2. Source and platform: input is a qualified FLAC variant; source length, channel/bit-depth facts, decoder seek implementation/version and precision pass IP-02 certification. Range `[start, start+samples)` is checked in **sample integers** against `image_samples`; CUE 75-fps mapping is inherited unchanged. **Before launching a worker, require an actually supported `ToolRunner::run_pipeline` on the executing platform** (currently Unix-only in `src/convert/pipeline/tool.rs:2170-2372`). A supported external FFmpeg seek command does not establish runner support. On non-Unix, keep existing routing unchanged unless a separately qualified pipeline runner is supplied.
3. Plan: every selected member has the **same** successful `prepare_cue_stream_direct_track_plan` result already authorized by `track_executor.rs:1355-1539`; FLAC output, unchanged rate/bit depth and no intentional DSP; no registered effects/HDCD, true-peak, gain, de-emphasis, dither, resampling, DC shift, DSD, ReplayGain transformation, or unverified container shapes. ReplayGain **tag analysis** is separate from audio DSP and must be honored.
4. Album policy: track selection, source/album ReplayGain authority, artwork, extended metadata and any metadata-only CUE origin can be represented without downgrading existing semantics. Reject otherwise; do not silently discard gain data or attach one track's observer to another.
5. Resource admission: acquire scoped **existing shared tool-family permits** for all simultaneously live S3 children *before spawn* (nonblocking whole-set acquisition, or equivalent no-partial-hold ordering). Impose one simple cap on live S3 workers across album groups, plus at most that many source-range readers; each uses bounded pipes and a fixed documented FD/RAM allowance. Conservatively cap worker count against real process/FD/RAM headroom; do not add a generic resource scheduler. If two workers cannot run within the existing shared limits, retain the existing route.
6. Workload: track count and cost heuristics favor parallel route only after empirical crossover (e.g., many mid/long tracks on SSD); no fixed heuristic counts may be labeled qualified before IP-06 trials. Manual opt-in pilot only before automatic promotion.
7. No partial parallel start followed by **silent replay** through S1 on process error. Prelaunch ineligibility falls back to S1; errors after launch are reported under **existing** `FailurePolicy`, artifacts invalidated as necessary and cancellation propagated. Retry is a new explicit attempt with clean staging and logging.

## Process, memory, I/O, and FD invariants

- **Global existing tool tokens**: use the shared `ToolConcurrencyLimits` owned by the conversion processor; obtain the appropriate number of per-family permits for each pair of *simultaneously live* S3 decoder/encoder processes. Try-acquire the complete set before launch, in canonical family order, releasing any partial set on refusal. Hold one RAII owner around the existing `ToolRunner::run_pipeline` call and do **not** acquire a second set inside that call. No permit waits while holding a partial set; no production-wide semaphore rewrite.
- **Memory**: existing bounded pipe transfer plus `N` live workers bounds transport memory to O(N), not O(album duration). Use a conservative fixed in-flight S3 cap and tested per-worker high-water headroom, not a new general memory-token service. No whole-track PCM queues or `.wav` staging on S3; checked integer byte counts.
- **FD**: no more than `N` supervised two-child pipelines, each with a bounded small set of pipes, files and stderr captures. Verify actual peak handles in concurrent-album stress tests and lower N if normal desktop limits are approached; no FD reservation ledger needed for this fixed worker shape.
- **I/O**: one source reader per admitted S3 worker; the same globally shared N bound prevents independent albums multiplying range-reader count. Prefer legacy S1 on storage classes with measured seek contention. Avoid pretending to control unmeasurable disk bandwidth.
- **CPU**: count live decoder and encoder processes against the existing global per-family permits; do not increase existing unrelated work concurrency or silently substitute one permit for two simultaneous FFmpeg children.
- **Cancellation**: one parent cancellation token; each runner owns both child exits; timeout and stop close write ends, terminate descendants, collect status and free reservations; completion aggregation is deterministic by original track index, not finish order.

## ReplayGain, accuracy, records, and publication

**Critical asymmetry:** Convert UI ReplayGain defaults `Both` (`src/tui/app.rs:5546-5554`). Existing qualified S1 on Unix can observe source-pass audio using FIFOs (`stages.rs:44480-44943`). Parallel S3 cannot reuse that shared sequential mirror unmodified. Initial S3 can run TonePoet's existing **post-output native ReplayGain analysis** after all track artifacts are staged, preserving tag semantics but at the cost of a reread. The pilot must actually measure total elapsed time **with `Both` on**. If source-pass/after-output analyzer gives different results on apparently identical PCM, investigate sample-domain equivalence or exact program semantics and reject pilot; not a tolerance handwave. A later source-range observer is **conditional**, with an album barrier, explicit failure policy and album-gain aggregation keyed by track identity.

Each worker should reuse the ordinary planner's single authorized encoder shape, staging paths, version cache, expected sample counts, final sample/depth validator, metadata/ReplayGain result, immutable `TrackId`, and execution-evidence model. Represent one range reader plus one encoder as distinct executed commands; do **not** attribute a whole-image decoder run to N tracks when actually N seek readers run. Successful completed workers return `ScheduledTrackOutput`s **only**; existing `publish_album_output_with_authority` (`stages.rs:27553`) owns output visibility. Respect both fail-closed and `AllowPartialAlbum` policy. Never accidentally expose a partial album merely because one worker finished early.

## Reversal gates and explicit exclusions

- **Boundary false**: if any qualified FLAC variant/input seek produces missing/repeated/wrong samples or cannot prove exact end-of-range under the chosen tool stack, keep S1 and revisit `flac --skip/--until` or native upstream API **only under a new qualification packet**. No whole-source-decode-per-worker fallback masquerading as parallel seeks.
- **Resource false**: if nested permit accounting deadlocks, an external child escapes cancellation, or capacity cannot be enforced across CUE and unrelated jobs, do not activate S3.
- **Semantic false**: if ReplayGain, metadata precedence, per-track provenance, verification or publication differs unexpectedly, reject activation. Do not lower defaults to make a benchmark pass.
- **Performance false**: if representative full-run median speedup is absent or slowdowns harm ordinary 1–3-track workloads, keep S1 default and S3 disabled/opt-in only if operationally useful.
- **Complexity false**: if production changes require duplicating the planner, native gain engine or safe publication, stop and reconsider whether the remaining performance opportunity warrants this design.

**Not selected now:** custom FLAC parser/decoder, universally seekable audio formats, universal CUE refactor, process pools per codec, PCM album caching, new thread pool, replacing the published output workflow, and concurrent per-track DSP for album-stateful operations.
