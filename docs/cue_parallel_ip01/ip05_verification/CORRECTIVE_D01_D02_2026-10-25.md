## D-01: selected source arrays are not the authored album

`materializer_cue.rs` derives `album_metadata.total_tracks` from the complete
`cue_input.sheet.tracks` **before** applying `req.source.track_selection` and
constructing `PreparedSource.tracks`. Hence a 12-member original CUE with only
members 1 and 2 selected produces both `source.tracks.len() == 2` and
`scheduler_tracks.len() == 2`, despite `album_metadata.total_tracks == 12`.
The previously delivered gate compared only the already-filtered lists.

The corrective admission check now also requires:

```rust
source.tracks.len() == source.album_metadata.total_tracks as usize
```

It runs before `prepare_qualified_flac_ranges_for_group`, with the original
rejection reason and the original whole-album S1 fallback. No child or permit
is acquired on rejection, and an explicitly Range-/Set-selected complete album
is not rejected by selection *type*. There is no new CUE parser, scheduler or
publication path.

New named regression:
`cue_ip05_pilot_incomplete_materialized_album_falls_back_before_spawn`.
It constructs the real materialized *shape* with two consecutive selected
members and the original authored total of 12. It asserts the specific
prelaunch decline and `try_encode_cue_s3_pilot(...).await == None`, unchanged
shared FFmpeg permits and no visible output. The positive count control
changes only the authored total to two and asserts that the admission proceeds
to the existing typed FLAC source proof (which declines the synthetic
placeholder); existing native 3-track/12-track positive pilot tests are
retained. **All Rust tests are NOT RUN on this authoring environment.**
