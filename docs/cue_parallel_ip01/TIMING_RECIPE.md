## Reproducible fixture and settings

On a qualified **Unix** TonePoet build host, choose one real, reproducible, representative single-image FLAC+CUE album and one test generated from the amended plan's `tools/generate_cue_fixture.py`. Record SHA-256 of **both the FLAC and CUE**; record original sample rate/bit depth/channels, `ffmpeg -version`, `ffprobe -version`, SoX/FLAC versions and SHA-256 of the exact installed TonePoet binary. Use a 16-bit 44.1 kHz stereo FLAC+CUE→FLAC case with unchanged sample rate and depth, default naming, no DSP, no de-emphasis, no HDCD, no merge, no true-peak gain, identical encoder presets, and the same metadata/artwork treatment. Identify whether a source-pass mirror was *actually applied*, rather than guessing from eligibility, especially on non-Unix hosts.

- Run S1 with **ReplayGain `Off`** and **ReplayGain `Both`** as independent, same-input trials. The Convert UI default is `Both`; explicitly select `Off` for the control. After IP-04/IP-05, match both settings for S3; S3 does **not** yet exist at IP-01.
- Use a paired configuration SHA-256 generated from canonical JSON of all fixed controls **excluding** only the route (`S1`/`S3`), ReplayGain mode (`Off`/`Both`) and run-specific output/log locations. Also record the *full run settings fingerprint* separately. The per-pair canonical SHA must match between all comparable cells, including tool versions, input hashes, CPU/core/parallel limits, stage flags and FS topology.
- Hold worker budget, tool permits, power profile, output destination volume, scratch location, failure/overwrite policy, and cache state constant. Record `stat -f -c '%T %d' <scratch_dir> <output_dir>` on Linux or the host's equivalent. Use fresh output directories or clean staging **between** repetitions; never include cleanup in just one route's stopwatch.
- Run several repetitions (e.g., 5 or more per cell) with warm-up, interleave or randomize cell order, note warm/cold cache explicitly, and report distributions (median, spread) **separately** for `Off` and `Both`. Do not average speedups from mismatched modes or cache states.

## Capture

1. Before launching TonePoet for **each trial**, choose a fresh absolute diagnostics file outside the album output tree and set `TONEPOET_PIPELINE_BASELINE_JSONL=/private/test/trace-<trial>.jsonl` in that process environment. This is **opt-in**; setting the variable after the process has initialized the diagnostic sink is not sufficient. Use one album per process for repeatable host resource conditions; only **explicitly correlated** new native scan events may be attributed to a CUE run, regardless of the number of jobs. Restrict diagnostics file permissions and retain it as private test evidence, because *existing* baseline event classes may contain full paths.
2. Record a host-controlled monotonic elapsed stopwatch from the **accept conversion action** through **visible terminal TUI repaint** (`action_to_visible_ms`). Neither action acceptance nor actual repaint is recorded by IP-01; report them from the controlled host stopwatch. `ConversionRunTiming` gives a separate pipeline wall span; never equate the two.
3. Record native `conversion.log` (which already embeds `ConversionRunTiming` when available), JSONL baseline, scheduler snapshot (`workers_busy`, `ready_queue_depth`, `peak_queue_depth`, `tool_runtime_ns_total`, `commands_started`), terminal status, observed output publication and sample/metadata checksums. The scheduler counters are process-wide; use a quiescent host if interpreting them per album.
4. Run `python3 -B docs/cue_parallel_ip01/tools/trace_summary.py /private/test/trace-<trial>.jsonl --output /private/test/summary-<trial>.csv`. Keep unabridged JSONL and the exact source/binary/fixture hashes as the receipt; the summary is derived evidence, not a standalone performance proof.
5. Fill one row per **route × ReplayGain × repetition** in `TIMING_WORKSHEET.csv`. Separate `replaygain_application_path=source_pass` (**selected**) from **`replaygain_application_settled.path=source_pass` with `succeeded=true` and `tag_action=applied`** (**metadata applied**). A retained `source_pass_replaygain_result` is measurement evidence only. Include `source_pass_observer_recovery_retry` episodes, physical group count and attempt count. For output scanning, `post_output_replaygain_worker_settled` is an inclusive worker+analysis+metadata duration; the existing native `replaygain_measure_started/finished` scope is scan-only **only when both carry the exact same CUE `cue_run_id` as the worker**. Legacy uncorrelated events, single-run event counts, and matching `item_id` are not identity proofs. A `post_output_candidate` event alone does *not* prove that a scan occurred; negative or non-finite durations are rejected; missing durations are `NOT INSTRUMENTED` and are never estimated.

## Interval authority and limitations

| Signal | What it actually measures | What it is NOT |
|---|---|---|
| `queue_deferred` / `queue_admitted` / `work_started` | First rejected submission (`queue_busy` or `queue_full`)→successful admission and, **separately**, successful admission→worker start | The TUI acceptance time or one additive total; a cancellation before admission leaves admission interval `NOT INSTRUMENTED` |
| `work_finished.elapsed_ms` | Full async album-group work unit, including planning, source-pass observer, conversion and cleanup | Decoder-only or encoder-only, or pipeline terminal time |
| `route_selected`, `source_pass_observer_recovery_retry` | S1/fallback per physical group and distinct attempt; one recovery episode may produce a second S1 attempt for the same group | Multiple physical groups or proof conversion succeeded; failures also use `route_execution_refused` |
| `s1_transport_settled.elapsed_ms` | One shared decoder + sequential consumers as a transport wall | Sum of child runtimes; child lifetimes overlap |
| `s1_child_lifetimes` | Runner-reported decoder and per-output encoder durations for **successful** segmented execution | True global CPU time or failed-child lifetimes; add no child elapsed values |
| `source_pass_track_observer_settled` | Existing source-pass FIFO observer's read/wait/analyse time per track | New observer implementation or net overhead; overlaps source decoder and other readers |
| `source_pass_observer_settled` | Concurrent observer/transport join envelope | Cost to add to transport wall |
| `replaygain_application_path`, `replaygain_application_settled` | Selected gain strategy **versus** actual success, failure or tag-skip recorded after Result settlement | The selected path alone is never proof of tag application or published outcome |
| `post_output_replaygain_worker_settled` | Host blocking wait + native measurement + tag write, on the actual output path | Pure scan cost; use explicitly CUE-token-correlated native scan events when present |
| `replaygain_measure_started/finished` with `cue_run_id` | Existing native scan-only scope, correlated directly to the opt-in CUE worker; non-additive with worker elapsed | An untagged native event or mere uniqueness/cardinality cannot be attributed to a CUE run; report `NOT INSTRUMENTED` |
| `report_terminal`, `album_published` | Pipeline event submission boundary and presence of published album (even if actions later fail) | Actual repaint; even emitted event can precede visible frame |
| Existing `stage_finished`, `run_finished`, `ConversionRunTiming` | Existing stage/pipeline spans | New fine-grained FFprobe/publication/tUI stage timings when source does not separate them |

Explicitly record `NOT INSTRUMENTED` for original request acceptance, actual TUI repaint and any additional decode/FFprobe/materialization/publication intervals not separated in the existing pipeline. `first_deferral_to_admission_ms` and `queue_to_start_ms` are separate intervals; neither equals action-to-worker latency. Observer timing uses both local group index and authored `track_ordinal`; avoid joining tracks solely by the local index. A trial with an absent/failed terminal result or unpublished album cannot qualify for performance promotion even if some intermediate timing exists. A failed run with incomplete CUE markers must not acquire synthetic durations. **JSONL append order is not a causal order**: scheduler admission capture precedes the worker start, but asynchronous output can be written later; use the monotonic timestamp and group ID for attribution.

## IP-06 decision (planning authority, not an IP-01 implementation)

Compare S1 and S3 under **both** ReplayGain `Off` and `Both` on matched pairs. Record if S1 actually used source-pass analysis, and if S3 incurred an additional post-output scan. If S3 wins meaningfully with `Off` but loses with `Both` **primarily** because of the separately measured output analysis pass, verdict is **`deferred`**: keep S1 the default, retain the S3 pilot opt-in, commission the narrowly scoped **PX-C** source-pass observer *then* repeat qualification. Do not implement PX-C before the measured trigger; do not promote S3 without a demonstrated end-to-end `Both` gain. If S3 loses with `Off`, extra observer complexity is not a presumed remedy.

**IP-01 implements no source-pass ReplayGain observer, no S3 worker or transport.** It adds timings around the **preexisting S1** native source-pass observer only.
